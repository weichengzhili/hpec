# 实时内核与 PREEMPT_RT

> 模块目录：`workspace/kernel/realtime/` · 接口文件：`include/realtime.h`

## 1. 模块定位与目标
建立 Linux 实时能力方案：PREEMPT_RT 完全抢占内核、实时调度、中断线程化、优先级继承，实现有界延迟的硬实时/软实时应用。

**服务场景**：工业机器人运动控制、汽车域控实时任务、网关实时控制环。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 抢占 | 完全抢占（PREEMPT_RT） |
| 调度 | SCHED_FIFO/RR/DEADLINE |
| 约束 | 最坏延迟需有界、可测量 |

## 3. 架构设计

### 3.1 PREEMPT_RT 关键特性
| 特性 | 说明 |
|------|------|
| 完全抢占 | 内核态几乎处处可抢占 |
| 中断线程化 | 中断处理为内核线程 |
| 自旋锁 → rt_mutex | 可睡眠、优先级继承 |
| 高精度时钟 | hrtimer |

### 3.2 实时调优
- CPU 隔离（isolcpus）给实时任务。
- 禁用中断合并/电源管理对实时核影响。
- 实时任务绑定专用核 + 高优先级。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `preempt_model_t` | 抢占模型 |
| `preempt_get_model()/enable_rt()/disable_rt()` | 抢占配置 |
| `irq_force_threaded()` | 中断线程化 |
| `rt_isolate_cpu()/unisolate_cpu()` | 核心隔离 |
| `hrtimer_start()/cancel()` | 高精度时钟 |
| `latency_measure_start()/stop_ns()` | 延迟测量 |

## 5. 关键流程与时序
实时任务就绪 → 抢占当前 → 立即运行。中断线程化后中断处理可被更高优先级实时任务抢占，延迟有界。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 内核 | PREEMPT_RT | 标准 | 完全抢占 |
| 隔离 | 实时核专用 | 共享 | 确定性 |
| 中断 | 线程化 | 原生 | 优先级可调 |

## 7. 性能指标（KPI）
- 最坏/最大调度延迟（cyclictest 量化，如 < 100µs）。
- 抖动（jitter）。

## 8. 可靠性设计
- 优先级继承防反转（见 lock）。
- 实时任务隔离防干扰。

## 9. 安全设计
- 实时任务资源限制防抢占风暴。
