# 进程调度

> 模块目录：`workspace/kernel/scheduler/` · 接口文件：`include/sched.h`

## 0. 问题定位

- **解决什么问题**：CFS/实时调度如何在多核上正确分配 CPU，满足实时任务 deadline。
- **边界标准**：
  1. 实时任务优先级正确，不受普通任务抢占（硬约束）。
  2. CPU affinity 隔离实时核（硬约束）。
  3. deadline miss 可检测和上报（硬约束）。
- **系统位置**：环 7；`lock`、`fsm` → 本模块 → `realtime`。

## 1. 模块定位与目标
建立进程/线程调度方案：CFS 公平调度、实时调度策略（SCHED_FIFO/RR/DEADLINE）、优先级与亲和性配置，满足多核负载均衡与实时任务隔离。

**服务场景**：域控/机器人实时任务、网关多服务、AI 推理与采集任务隔离。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 策略 | CFS、SCHED_FIFO/RR/DEADLINE |
| 多核 | RK3588 8 核负载均衡 |
| 实时 | 实时任务优先、延迟有界 |
| 约束 | 实时任务与普通任务隔离 |

## 3. 架构设计

### 3.1 调度类
| 调度类 | 优先级 | 说明 |
|--------|--------|------|
| deadline | 最高 | 周期任务截止时间 |
| realtime (FIFO/RR) | 高 | 固定优先级 |
| CFS | 普通 | 公平时间片 |

### 3.2 关键机制
| 机制 | 说明 |
|------|------|
| 优先级 | nice 值 / 实时优先级 |
| 亲和性 | CPU affinity 绑定核心 |
| 隔离 | cpuset/isolcpus 隔离核心 |
| 抢占 | PREEMPT_RT 完全抢占（见 realtime） |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `sched_policy_t/sched_param_t` | 策略与参数 |
| `sched_set_policy/get_policy()` | 策略设置 |
| `sched_set_affinity/get_affinity()` | 亲和性 |
| `sched_isolate_cpu/release_cpu()` | 核心隔离 |
| `sched_priority_ceil()` | 优先级上限（反转防护） |

## 5. 关键流程与时序
任务就绪 → 调度器选择（按类优先级）→ 切换上下文 → 运行。实时任务随时抢占普通任务。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 实时任务 | 绑定专用核心 | 共享 | 确定性、防干扰 |
| 隔离 | isolcpus/cpuset | 无 | 关键任务独占 |
| 策略 | FIFO/DEADLINE 按需 | 单一 | 实时保证 |

## 7. 性能指标（KPI）
- 调度延迟、上下文切换时间。
