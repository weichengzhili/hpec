# 工作队列与内核线程

> 模块目录：`workspace/kernel/workqueue/` · 接口文件：`include/workqueue.h`

## 0. 问题定位

- **解决什么问题**：异步任务如何从 ISR 安全下放。
- **边界标准**：
  1. 工作项正确排队，无阻塞 ISR，无泄漏。
- **系统位置**：环 4。

## 1. 模块定位与目标
建立内核后台任务机制：工作队列（workqueue）与内核线程（kthread），用于延后处理、周期性任务、可睡眠的后台工作。

**服务场景**：驱动延后处理、周期监控任务、慢速 IO、定时上报。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 机制 | workqueue（系统/专用）、kthread |
| 约束 | 可睡眠（区别于 softirq） |
| 约束 | 实时场景用专用 workqueue 提升优先级 |

## 3. 架构设计

### 3.1 机制对比
| 机制 | 说明 | 场景 |
|------|------|------|
| workqueue | 队列化工作，内核线程执行 | 延后/周期 |
| kthread | 独立内核线程 | 长期任务 |
| 专用 workqueue | 独立线程池，可调优先级 | 实时 |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `work_fn_t/work_struct_t` | 工作项 |
| `schedule_work()/schedule_delayed_work()` | 调度 |
| `flush_work()/cancel_work()` | 同步/取消 |
| `alloc_workqueue()/queue_work()/destroy_workqueue()` | 专用 workqueue |
| `kthread_run()/kthread_stop()/kthread_should_stop()` | 内核线程 |

## 5. 关键流程与时序
中断/进程提交工作 → workqueue 调度 → 内核线程执行 → 完成。延迟工作按时间唤醒执行。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 延后处理 | workqueue | softirq | 简单、可睡眠 |
| 实时 | 专用 workqueue + 高优先级 | 系统 | 保证响应 |
| 长期任务 | kthread | workqueue | 独立运行 |
