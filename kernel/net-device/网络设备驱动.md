# 网络设备驱动

> 模块目录：`workspace/kernel/net-device/` · 接口文件：`include/netdev.h`

## 0. 问题定位

- **解决什么问题**：网络设备如何通过 netdev/NAPI 收发。
- **边界标准**：
  1. netdev 生命周期安全，NAPI 正确，无丢包泄漏。
- **系统位置**：环 5。

## 1. 模块定位与目标
建立网络设备驱动与网络栈方案：netdev 驱动模型、NAPI 收包、协议栈交互，支撑以太网/无线网络通信。

**服务场景**：工业网关（双千兆、TSN）、IoT 边缘（WiFi/5G）、域控车载以太网。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 模型 | net_device / NAPI |
| 约束 | 高吞吐收包需 NAPI 减少中断 |
| 约束 | TSN 等实时以太网需特殊支持 |

## 3. 架构设计

### 3.1 网络栈层次
```
应用 → socket → 协议栈(TCP/UDP/IP) → netdev 驱动 → 硬件
```

### 3.2 NAPI
- 收包中断 → 轮询（poll）批量收包。
- 减少中断频率，提升高吞吐性能。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `net_device_t` | 网络设备 |
| `netdev_ops_t` | 设备操作（open/stop/xmit/set_mac） |
| `netdev_register/unregister()` | 注册 |
| `napi_enable/disable/schedule/complete()` | NAPI 控制 |
| `netif_receive()` | 收包上交协议栈 |
| `netdev_rx/tx_packets()` | 统计 |

## 5. 关键流程与时序
收包：中断 → NAPI 调度 → poll 收包 → 交给协议栈。发包：协议栈 → xmit → 硬件。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 收包 | NAPI | 纯中断 | 高吞吐低中断 |
| 卸载 | 硬件校验/分片卸载 | 软件 | 降低 CPU |
| 实时 | TSN/PTP | 无 | 网关/车载 |
