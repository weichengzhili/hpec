# 内核调试

> 模块目录：`workspace/kernel/debug/` · 接口文件：`include/debug.h`

## 1. 模块定位与目标
建立内核调试体系：printk/dynamic debug、kgdb、ftrace、kprobe、oops/panic 分析、内存错误检测（KASAN），快速定位内核问题。

**服务场景**：内核/驱动排障、稳定性分析、性能瓶颈定位。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 手段 | printk、ftrace、kprobe、kgdb、KASAN |
| 约束 | 调试手段对性能影响需可控 |
| 约束 | 生产内核需裁剪调试功能 |

## 3. 架构设计

### 3.1 调试手段
| 手段 | 用途 |
|------|------|
| printk | 日志（分级、dynamic debug） |
| ftrace | 函数追踪、性能分析 |
| kprobe | 动态插桩 |
| kgdb | 内核在线调试 |
| KASAN | 内存错误检测 |
| oops/panic | 崩溃信息分析 |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `printk_log()` | 日志输出 |
| `dynamic_debug_enable/disable()` | 动态调试 |
| `ftrace_function_start/stop()/trace_printk()` | 追踪 |
| `kprobe_register/unregister()` | 插桩 |
| `panic_dump_registers()/store_stack()/oops_report()` | 崩溃分析 |
| `kasan_check_range()` | 内存检测 |

## 5. 关键流程与时序
崩溃 → 输出 oops/panic 信息（寄存器/调用栈）→ 转储 → 复位。定位用 ftrace/kprobe 追踪。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 日志 | dynamic debug | 全开 | 生产零开销 |
| 追踪 | ftrace | 无 | 低开销、全面 |
| 内存 | KASAN（调试版） | 无 | 定位内存错误 |

## 7. 性能指标（KPI）
- 调试开销可控。
- 问题定位效率。

## 8. 可靠性设计
- panic 转储完整、可追溯。

## 9. 安全设计
- 生产禁用调试接口（防攻击）。

## 10. 测试与验证策略
- 故障注入、KASAN 检测。
- 调试流程验证。

## 11. 集成与部署
- 调试/生产内核分离配置。
