# 安全与加固

> 模块目录：`workspace/kernel/security/` · 接口文件：`include/security.h`

## 0. 问题定位

- **解决什么问题**：LSM/seccomp/内存保护如何隔离进程，防止越权和漏洞利用。
- **边界标准**：
  1. 权限最小化，无多余特权（硬约束）。
  2. 越权访问被拒绝并记录（硬约束）。
  3. 攻击面最小，未用子系统/接口关闭（硬约束）。
- **系统位置**：环 8；`memory-model`、`lock` → 本模块 → `kernel/debug`。

## 1. 模块定位与目标
建立内核安全加固方案：最小权限、LSM（SELinux/AppArmor）、内存保护、系统调用过滤、启动安全，构建纵深防御。

**服务场景**：域控/IoT 边缘信息安全（ISO 21434）、网关安全、防攻击。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 机制 | LSM、capabilities、seccomp、ASLR |
| 约束 | 加固与性能/兼容平衡 |
| 约束 | 遵循最小权限原则 |

## 3. 架构设计

### 3.1 加固层次
| 层 | 机制 |
|----|------|
| 权限 | capabilities、用户/组 |
| 访问控制 | LSM（SELinux/AppArmor） |
| 系统调用 | seccomp 过滤 |
| 内存 | ASLR、NX、栈保护 |
| 启动 | 安全启动链（见 platform/uboot） |

### 3.2 纵深防御
多层面结合，单一层失效不致命。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `capability_mask_t` | 能力掩码 |
| `security_check/set_capability()` | 能力检查 |
| `lsm_register_hook()/enforce()` | LSM 钩子 |
| `seccomp_install_filter()` | 系统调用过滤 |
| `security_set_aslr()/set_nx()` | 内存保护 |
| `security_audit_log()` | 审计 |

## 5. 关键流程与时序
系统调用 → 权限检查（capability）→ LSM 钩子 → 访问控制 → 执行。越权即拒绝。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 访问控制 | SELinux/AppArmor | 仅权限 | 强制访问控制 |
| 系统调用 | seccomp | 无 | 最小暴露面 |
| 内存 | ASLR/NX | 无 | 防利用 |

## 7. 性能指标（KPI）
