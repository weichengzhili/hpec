# 中断与下半部

> 模块目录：`workspace/kernel/irq/` · 接口文件：`include/irq.h`

## 1. 模块定位与目标
建立 Linux 中断处理体系：上半部（硬中断）、下半部（softirq/tasklet/threaded irq），平衡中断响应速度与处理时长，保障实时性与系统吞吐。

**服务场景**：RK3588 外设驱动、实时控制中断、网关报文接收、机器人编码器中断。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 上半部 | 快速响应、不可阻塞 |
| 下半部 | 延后处理、可部分阻塞 |
| 约束 | 上半部时长最小化（见 concurrency/interrupt-critical） |

## 3. 架构设计

### 3.1 下半部机制
| 机制 | 说明 | 阻塞 |
|------|------|------|
| softirq | 内核预定义，快速 | 否 |
| tasklet | 基于 softirq，简化 | 否 |
| threaded irq | 内核线程处理 | 是 |
| workqueue | 内核线程，可睡眠 | 是 |

### 3.2 分工
- 上半部：清中断、必要操作。
- 下半部：数据处理、耗时操作。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `irq_request()/request_threaded()/free()` | 中断注册 |
| `irq_enable/disable/set_affinity()` | 中断控制 |
| `softirq_raise()/tasklet_schedule()` | 下半部调度 |
| `irq_count()` | 中断统计 |

## 5. 关键流程与时序
中断触发 → 上半部 → 调度下半部 → 下半部执行 → 完成。threaded irq 用内核线程执行处理函数。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 上半部 | 极简 | 全处理 | 降低中断延迟 |
| 下半部 | threaded irq / workqueue | softirq | 可睡眠、灵活 |
| 实时 | 线程化中断 | 纯中断 | 优先级可调 |
