# 链接脚本与启动流程

> 模块目录：`workspace/boot/startup/` · 接口文件：`include/startup.h`

## 0. 问题定位

- **解决什么问题**：从复位向量到 `main`，如何保证内存段正确初始化、栈可用、镜像可信。
- **边界标准**：
  1. `.data` 拷贝和 `.bss` 清零必须早于任何 C 运行，顺序可静态验证（硬约束）。
  2. 启动自检（`.data` 校验和、栈水位）在 `main` 前完成（硬约束）。
  3. 冷/热/看门狗/软复位四种路径到达一致的可运行态（度量项）。
- **系统位置**：环 1；`clock-power` → 本模块 → `memory-model`、`gic`。

## 1. 模块定位与目标
定义从芯片上电到 C 运行时就绪（进入 `main`）的完整启动链路：复位向量、栈初始化、段拷贝/清零、时钟与看门狗初始化、跳转主程序。是裸机/RTOS/MCU 平台的根基，也是理解 SoC 启动（platform/uboot）的前提。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 启动时间 | 上电到 main 时间受产品指标约束 |
| 多级启动 | SoC 场景：ROM → Bootloader → 内核（见 platform/uboot） |
| 约束 | 启动代码运行在 C 运行时未就绪阶段，只能用受限原语 |

## 3. 架构设计

### 3.1 链接脚本职责
- 定义段与符号（`_start`、`__bss_start__` 等）。
- 指定入口点、向量表地址、堆/栈边界。
- 输出 `.map` 供地址审计。

### 3.2 启动流程（无 OS）
```
复位 → 硬件初始化 → 设置 SP → 拷贝 .data（ROM→RAM）→ 清零 .bss
     → 初始化 C 运行时（可选全局构造器）→ 时钟/看门狗/中断配置 → main()
```

### 3.3 启动代码分层
1. **汇编层**：最早期，设置 SP、跳转。
2. **C 启动层**：段初始化、时钟配置。
3. **应用 main**：业务入口。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `_start()` | 启动入口（由复位向量跳转） |
| `startup_copy_data()/zero_bss()/init_c_runtime()` | 段初始化 |
| `system_init()/board_init()` | 系统/板级初始化 |
| `clock_init()/watchdog_init()/interrupt_init()` | 时钟/看门狗/中断 |
| `startup_image_crc_check()/signature_check()` | 镜像完整性校验 |

## 5. 关键流程与时序
- `.data` 拷贝必须在任何全局变量读之前完成。
- `.bss` 清零必须在 `main` 前完成。
- 时钟初始化顺序：先低频内部时钟稳定，再切高频 PLL。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 启动语言 | 汇编最小化 + C 主体 | 全汇编 | 可读可维护 |
| 段布局 | .vectors 固定在低地址 | 任意 | 中断控制器要求 |
| 看门狗 | 启动早期配置 | 延迟 | 防启动卡死 |
| 启动校验 | CRC/签名校验 | 无 | 完整性保障 |

## 7. 性能指标（KPI）
- 上电到 main 时间量化（含时钟稳定）。
- 镜像体积（.text + .data）。
- 启动自检覆盖率。

## 8. 可靠性设计
- 启动失败看门狗复位 + 重试。
- 段初始化后自检（.bss 是否全零、关键数据校验）。
- 多镜像备份（A/B 分区，见 platform/uboot）。

## 9. 安全设计
- 安全启动链：ROM 校验 Bootloader，Bootloader 校验应用镜像。
- 向量表、启动代码置于只读/受保护区。
- 栈初始化使用安全随机基址（可选 ASLR）。

## 10. 测试与验证策略
- 启动时序测试（示波器/逻辑分析仪）。
- 段初始化正确性单测。
- 故障注入：镜像损坏、时钟失效。

## 11. 集成与部署
- 链接脚本、启动代码纳入版本受控。
