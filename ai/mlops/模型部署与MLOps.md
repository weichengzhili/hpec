# 模型部署与 MLOps

> 模块目录：`workspace/ai/mlops/` · 接口文件：`include/model_manager.hpp`

## 1. 模块定位与目标
建立模型从训练到部署的工程化体系（MLOps）：模型版本管理、转换/量化流水线、下发与回滚、监控与更新，实现模型生命周期可管理、可追溯。

**服务场景**：AI 边缘部署的模型管理、云边协同更新。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 版本 | 模型版本化、可追溯 |
| 下发 | OTA 下发、原子切换、回滚 |
| 约束 | 下发失败不影响线上（A/B） |

## 3. 架构设计

### 3.1 模型生命周期
```
训练 → 转换/量化 → 评测 → 注册 → 下发 → 部署 → 监控 → 更新/回滚
```

### 3.2 关键机制
| 机制 | 说明 |
|------|------|
| 模型仓库 | 版本化存储 + 元数据 |
| 下发 | OTA 通道（见 platform/uboot） |
| 切换 | A/B 原子切换 |
| 监控 | 精度/性能指标采集 |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `model_meta` | 模型元数据（版本/校验和/精度） |
| `model_slot` | A/B 槽位 |
| `register_model()/query_model()` | 注册/查询 |
| `download_model()/verify_model()` | 下发/校验 |
| `switch_model()/rollback()` | 切换/回滚 |
| `load_to_engine()/report_metric()` | 加载/监控 |

## 5. 关键流程与时序
新模型训练 → 转换量化 → 评测通过 → 下发 → 校验 → 原子切换 → 监控 → 异常回滚。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 切换 | A/B 原子 | 覆盖 | 失败可回滚 |
| 校验 | 签名+哈希 | 无 | 完整性/安全 |
| 监控 | 指标采集 | 无 | 质量闭环 |

## 7. 性能指标（KPI）
- 模型下发成功率、切换耗时。
- 回滚成功率、版本追溯完整。

## 8. 可靠性设计
- 下发失败重试、校验失败拒绝。
- 异常自动回滚。

## 9. 安全设计
- 模型签名/加密、下发通道加密（见 security）。

## 10. 测试与验证策略
- 下发/切换/回滚全链路测试。
- 故障注入（下发中断、校验失败）。
