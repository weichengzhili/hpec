# 推理框架选型

> 模块目录：`workspace/ai/framework/` · 接口文件：`include/inference_engine.hpp`

## 0. 问题定位

- **解决什么问题**：多框架如何统一接口、可切换。
- **边界标准**：
  1. 统一引擎接口，框架可替换。
- **系统位置**：环 7。

## 1. 模块定位与目标
建立边缘推理框架选型方法：对比 RKNN、ONNX Runtime、NCNN、TFLite 等的算子支持、性能、易用性、生态，按场景选择最优框架。

**服务场景**：边缘 AI 部署的框架决策。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 候选 | RKNN / ONNX Runtime / NCNN / TFLite / OpenVINO |
| 约束 | 与 RK3588 NPU 适配、算子支持、生态 |

## 3. 架构设计

### 3.1 框架对比维度
| 维度 | 说明 |
|------|------|
| 算子支持 | 模型所需算子覆盖 |
| 性能 | 延迟/吞吐/内存 |
| 硬件加速 | NPU/GPU 支持 |
| 生态 | 工具链、社区 |
| 部署 | 交叉编译、集成难度 |

### 3.2 选型建议
- 优先 RKNN（RK3588 NPU 最佳性能）。
- 通用/多后端用 ONNX Runtime。
- 轻量 CPU 推理用 NCNN。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `engine_type` | 框架类型枚举 |
| `engine_info` | 引擎能力信息 |
| `inference_engine` | 统一推理引擎接口 |
| `create_engine()/destroy_engine()` | 工厂 |
| `engine_benchmark()` | 基准对比 |

## 5. 关键流程与时序
模型 → 转换（对应框架格式）→ 框架加载 → 推理 → 评测 → 决策。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| NPU 场景 | RKNN | 其他 | 硬件最优 |
| 通用 | ONNX Runtime | RKNN | 生态/灵活 |
| 抽象 | 统一接口 | 各框架 | 可替换 |

## 7. 性能指标（KPI）
- 各框架延迟/吞吐/精度对比。
- 内存占用对比。

## 8. 可靠性设计
- 框架稳定性、异常处理。

## 9. 安全设计
- 框架漏洞审计（供应链）。

## 10. 测试与验证策略
- 多框架基准测试（benchmark）。

## 11. 集成与部署
- 框架版本锁定。

## 12. 参考资料
