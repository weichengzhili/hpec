# 边缘 AI 安全与隐私

> 模块目录：`workspace/ai/security/` · 接口文件：`include/ai_security.hpp`

## 1. 模块定位与目标
建立边缘 AI 安全与隐私方案：模型保护（加密/签名/防逆向）、推理数据隐私、对抗攻击防护、供应链安全，保障 AI 资产与用户数据安全。

**服务场景**：舱内/车载隐私、工业检测数据保护、模型知识产权保护。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 模型保护 | 加密/签名/白盒（可选） |
| 隐私 | 本地推理、数据脱敏 |
| 对抗 | 对抗样本/投毒防护 |
| 约束 | 安全机制不影响推理性能 |

## 3. 架构设计

### 3.1 安全层次
| 层 | 机制 |
|----|------|
| 模型保护 | 加密存储、运行时解密、签名校验 |
| 数据隐私 | 本地推理、最小化上传 |
| 供应链 | 模型/框架来源审计 |
| 对抗防护 | 输入校验、鲁棒性 |

### 3.2 信任链
- 模型签名校验（见 mlops）。
- 与安全启动信任链结合（见 platform/uboot）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `ai_model_encrypt/decrypt()` | 模型加解密 |
| `ai_model_sign/verify()` | 签名/校验 |
| `ai_data_anonymize()/minimize()` | 数据脱敏/最小化 |
| `ai_input_validate()/adversarial_detect()` | 输入校验/对抗检测 |
| `ai_model_source_verify()` | 供应链审计 |

## 5. 关键流程与时序
加载模型 → 校验签名 → 解密 → 推理 → 结果脱敏 → 输出。上传数据最小化。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 推理 | 本地为主 | 云端 | 隐私 |
| 模型 | 加密+签名 | 明文 | 防逆向/篡改 |
| 数据 | 最小化上传 | 全量 | 隐私 |
