# 模型量化

> 模块目录：`workspace/ai/quantization/` · 接口文件：`include/quantization.hpp`

## 1. 模块定位与目标
建立模型量化方案：FP32 → INT8/FP16，通过校准（calibration）与混合量化，在精度可接受范围内降低模型体积与算力需求，适配 NPU。

**服务场景**：RK3588 NPU 部署、模型轻量化、低功耗推理。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 精度 | INT8（NPU 高效）/ FP16 |
| 校准 | 量化校准集、激活范围 |
| 约束 | 精度损失需可接受（量化前后比对） |

## 3. 架构设计

### 3.1 量化类型
| 类型 | 说明 |
|------|------|
| 训练后量化（PTQ） | 校准数据确定范围 |
| 量化感知训练（QAT） | 训练时模拟量化 |
| 混合量化 | 敏感层高精度 |

### 3.2 量化流程
```
FP32 模型 → 校准（统计激活范围）→ 量化（权重/激活 INT8）→ 精度评估 → 部署
```

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `quant_type` | 量化类型（int8/fp16/mixed） |
| `quant_config` | 量化配置（校准数据/精度目标） |
| `quant_result` | 结果统计（体积/精度） |
| `quantize_model()` | 量化 |
| `quant_evaluate_accuracy()` | 精度评估 |
| `quant_set_sensitive_layers()` | 混合量化敏感层 |

## 5. 关键流程与时序
加载 FP32 模型 → 跑校准数据统计 → 计算量化参数（scale/zero_point）→ 量化 → 精度验证 → 转 RKNN。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 精度 | INT8 为主 | FP32 | NPU 能效最高 |
| 敏感层 | 混合量化 | 全 INT8 | 平衡精度 |
| 方法 | PTQ 优先 | QAT | 简单、无需重训 |

## 7. 性能指标（KPI）
- 量化精度损失（< 1% 目标）。
- 模型体积/算力下降幅度。

## 8. 可靠性设计
- 量化精度回归（全量评测集）。
- 敏感层保护。

## 9. 安全设计
- 量化模型与原始模型一致性可审计。

## 10. 测试与验证策略
- 量化前后精度比对。
- 边界样本测试。

## 11. 集成与部署
- 量化流程脚本化，纳入 MLOps（见 mlops）。
