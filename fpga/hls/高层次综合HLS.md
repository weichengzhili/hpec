# 高层次综合 HLS

> 模块目录：`workspace/fpga/hls/` · 接口文件：`rtl/hls_wrapper.sv`

## 0. 问题定位

- **解决什么问题**：HLS IP 如何封装与优化。
- **边界标准**：
  1. 接口正确，优化不破坏语义。
- **系统位置**：环 5、环 7。

## 1. 模块定位与目标
用 C/C++ 高层次综合（HLS）将算法快速映射为硬件，缩短算法类模块开发周期，同时通过 pragma 优化吞吐/延迟/资源。适用于算法密集、迭代频繁的场景。

**服务场景**：AI/信号处理算法加速、视觉预处理、控制算法硬件化。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 语言 | C/C++（HLS 子集） |
| 工具 | Vivado HLS / 国产 HLS 工具 |
| 约束 | 需理解综合结果（接口、流水线、资源） |

## 3. 架构设计

### 3.1 HLS 流程
```
C/C++ 算法 → 仿真验证 → HLS 综合 → 接口/资源/流水线优化 → 导出 RTL/IP → 集成
```

### 3.2 优化手段
| 手段 | 说明 |
|------|------|
| 流水线 (pipeline) | 提升吞吐 |
| 展开 (unroll) | 并行化循环 |
| 数组分区 | 提升内存带宽 |
| 接口约束 | 指定 AXI/流接口 |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `hls_wrapper` | HLS IP 封装 |
| `ap_start/ap_done/ap_idle/ap_ready` | 控制握手 |
| `data_in/data_out` | AXI-Stream 数据流 |
| `ctrl` | AXI-Lite 配置 |

## 5. 关键流程与时序
算法仿真正确 → 综合 → 优化迭代（流水线/展开）→ 资源/时序满足 → 导出集成。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 使用 | 算法密集模块 | 手写 RTL | 开发效率高 |
| 优化 | 流水线/展开 | 无 | 吞吐 vs 资源 |
| 验证 | C 仿真先行 | 直接综合 | 快速迭代 |

## 7. 性能指标（KPI）
- 吞吐/延迟、资源利用率。
- 综合结果与算法精度一致。

## 8. 可靠性设计
- C 仿真与 RTL 协仿真相一致。
- 定点化精度验证。

## 9. 安全设计
- 综合结果可审计（接口明确）。

## 10. 测试与验证策略

- 精度与性能回归。
