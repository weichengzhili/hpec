# 硬件抽象层设计

> 模块目录：`workspace/driver/hal/` · 接口文件：`include/hal.hpp`

## 0. 问题定位

- **解决什么问题**：硬件依赖如何通过接口抽象，使上层可测试、可替换。
- **边界标准**：
  1. HAL 接口不泄漏硬件裸指针，依赖注入可 mock（硬约束）。
  2. 每个 HAL 实现可脱离真实硬件跑单元测试（硬约束）。
  3. 错误返回统一 Result/错误码，无隐式失败（硬约束）。
- **系统位置**：环 3；`bit-register` → 本模块 → `driver-dev`、`platform-driver`。

## 1. 模块定位与目标
用 C++ 接口抽象与依赖注入，把硬件访问与业务逻辑解耦，使上层代码可脱离具体硬件在主机上单元测试，同时支持多平台移植。是驱动可测试性、可维护性的关键。

**服务场景**：RK3588 外设抽象、域控跨 MCU 移植、网关多平台、AI 摄像头/传感器抽象。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 解耦 | 业务不直接触碰寄存器 |
| 可测试 | 接口可用 mock/fake 替换 |
| 零开销 | 抽象不引入虚函数开销（实时热路径） |
| 约束 | 抽象层接口稳定，实现可替换 |

## 3. 架构设计

### 3.1 分层
```
业务逻辑 ──依赖──> 抽象接口(HAL) <──实现── 具体硬件(RK3588/MCU/FPGA)
                          │
                     Mock/Fake（测试）
```

### 3.2 抽象实现方式
| 方式 | 开销 | 适用 |
|------|------|------|
| 虚函数接口 | 有虚调用开销 | 冷路径、可插拔设备 |
| 模板 + 依赖注入 | 零开销（静态） | 热路径 |
| CRTP | 零开销 | 静态多态设备 |
| 编译期配置 + 链接替换 | 零开销 | 平台实现替换 |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `igpio` | GPIO 抽象（set/get level、direction） |
| `iuart` | UART 抽象（read/write/flush） |
| `ispi` | SPI 抽象（transfer） |
| `ii2c` | I2C 抽象（read/write） |
| `iadc` | ADC 抽象（read_channel） |
| `hal_iface` | 接口聚合（依赖注入入口） |
| `static_gpio<Derived>` | CRTP 静态多态（热路径零虚调用） |

## 5. 关键流程与时序
构造时注入具体实现（或编译期绑定）→ 业务调用抽象接口 → 具体实现访问硬件。运行期分派（虚函数）仅用于冷路径，热路径用模板消除。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 热路径 | 模板/CRTP 静态多态 | 虚函数 | 零开销 |
| 可插拔 | 虚函数接口 | 模板 | 运行期替换灵活 |
| 测试 | 依赖注入 + Mock | 真硬件 | 主机可测 |
| 移植 | 平台实现单独模块 | 混杂 | 业务零改动 |

## 7. 性能指标（KPI）
- 热路径反汇编无虚调用。
- 业务代码主机单测覆盖率达标。

## 8. 可靠性设计
- 抽象接口契约明确，实现需满足错误处理约定。
- 设备实现带状态与错误上报（见 foundation/result）。

## 9. 安全设计
- 接口校验参数，防止非法句柄/地址。
- 设备访问权限控制（见 kernel/security）。

## 10. 测试与验证策略
- 业务逻辑用 Mock 全量主机单测。
- 硬件实现做片上集成测试。

## 11. 集成与部署
- HAL 接口版本化，实现模块化独立发布。
