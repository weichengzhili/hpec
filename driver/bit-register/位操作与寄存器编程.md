# 位操作与寄存器编程

> 模块目录：`workspace/driver/bit-register/` · 接口文件：`include/bit_register.h`

## 1. 模块定位与目标
建立外设寄存器操作的标准方法：位域定义、掩码、置位/清位/测试、位序换算，以及可读可维护的寄存器抽象层。目标是消除魔法数字、提升驱动可读性与正确性。

**服务场景**：RK3588 全部外设、MCU 外设、FPGA 寄存器映射。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 可读性 | 拒绝裸掩码 `0x3F`，用命名常量 |
| 正确性 | 读写-改-写（RMW）必须原子，避免破坏其他位 |
| 位序 | 区分 MSB-first 与 LSB-first，通信/存储场景显式换算 |
| 约束 | 位域(bit-field)实现依赖编译器，硬件寄存器场景慎用 |

## 3. 架构设计

### 3.1 寄存器描述分层
1. **寄存器定义层**：寄存器地址、字段位宽、位偏移的宏/常量。
2. **访问层**：READ/WRITE 封装（见 memory/memory-barrier）。
3. **语义层**：按功能封装成 `set_pin()`、`enable_clock()` 等有业务含义的接口。

### 3.2 位操作原语
| 原语 | 表达式 | 用途 |
|------|--------|------|
| 置位 | `v |= (1u << n)` | 使能位 |
| 清位 | `v &= ~(1u << n)` | 关断位 |
| 测试 | `(v >> n) & 1u` | 状态查询 |
| 字段提取 | `(v >> off) & MASK` | 读多 bit 字段 |
| 字段写入 | `(v & ~(MASK<<off)) | (val<<off)` | 写多 bit 字段 |

### 3.3 位域 vs 掩码
- 掩码方式：显式、可移植、可审计（**推荐用于硬件寄存器**）。
- 位域方式：语义清晰但布局由实现定义，仅用于内存数据结构且慎用。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `BIT/BIT_MASK/BIT_SET/BIT_CLEAR/BIT_TEST/BIT_TOGGLE` | 位操作宏 |
| `REG_FIELD_MASK/GET/SET` | 字段访问宏 |
| `reg_field_desc_t` | 字段描述（偏移/位宽） |
| `reg_read/reg_write` | 字段级读写（内部 RMW） |
| `reg_field_get/reg_field_set` | 显式字段提取/写入 |

**命名规范**：`<模块>_<寄存器>_<字段>`。

## 5. 关键流程与时序
RMW 流程：读寄存器 → 只改目标字段 → 回写。多核/中断共享寄存器时，RMW 需临界区保护（见 concurrency/interrupt-critical），否则竞态丢失并发写入。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 寄存器描述 | 掩码+偏移宏 | 位域 | 可移植、可审计 |
| 共享寄存器 | RMW 走原子/锁 | 裸 RMW | 防止并发破坏 |
| 只写/置1清零寄存器 | 区分访问语义 | 统一 RMW | 硬件特性导致不可 RMW |
| 类型 | 显式 uint32_t/uint64_t | int | 消除位宽不确定性 |

## 7. 性能指标（KPI）
- 热路径位操作编译后应为单条 BFI/ORR 指令（无函数调用）。
- 寄存器访问次数在 RMW 场景不超过 2 次（读+写）。

## 8. 可靠性设计
- 关键寄存器写后回读校验（W1C 等特殊语义单独处理）。
- 字段定义与芯片手册自动比对（脚本/CI）防漂移。

## 9. 安全设计
- 寄存器地址白名单校验，防止越界写入。
- 关键控制寄存器写使能需解锁序列，防误写。

## 10. 测试与验证策略
- 单元测试覆盖字段提取/写入边界（0、全 1、中间值）。
- 用 QEMU 或寄存器仿真模型做驱动读写回归。

## 11. 集成与部署
- 寄存器定义与驱动分层，头文件由芯片手册脚本生成并受控。
