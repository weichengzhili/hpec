# 内存管理与内存池

> 模块目录：`workspace/memory/memory-pool/` · 接口文件：`include/memory_pool.h`

## 1. 模块定位与目标
在无 GC、受限堆的环境下，建立确定性、可审计的内存分配策略：静态分配优先、内存池、固定块分配器、防泄漏与防碎片化机制。目标是把内存问题从运行期不可预测变成可静态验证。

**边界**：C 语言固定块内存池；C++ 分配器见 `memory/allocator`。

**服务场景**：工业网关（长连接缓存）、汽车域控（功能安全要求确定性）、边缘节点（多路流媒体缓冲）。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 确定性 | 禁止运行期不可预测的 malloc 抖动（安全关键路径） |
| 碎片 | 长期运行不允许堆碎片导致分配失败 |
| 可审计 | 每次分配/释放可追踪，便于查泄漏 |
| 约束 | 内存池大小需按业务峰值静态估算 |

## 3. 架构设计

### 3.1 分配策略分层
| 策略 | 适用 | 确定性 | 碎片 |
|------|------|--------|------|
| 静态分配 | 全局对象、缓冲 | 完全确定 | 无 |
| 栈分配 | 局部短生命周期 | 确定 | 无 |
| 固定块内存池 | 同类对象 | 确定 | 无 |
| 大小分级分配器 | 通用 | 准确定 | 低 |
| 通用 malloc | 非关键路径 | 不确定 | 有 |

### 3.2 内存池结构
```
┌─────────────┐
│ 池控制块     │ 块大小、块数、空闲链表头、used、high_water
├─────────────┤
│ 块 [0]      │ ─┐
│ 块 [1]      │  │ 空闲块通过链表串联（free-list）
│ ...         │  │
│ 块 [n-1]    │ ─┘
└─────────────┘
```
- 空闲块链表（free-list）挂在块头，O(1) 分配/释放。
- 记录高水位（high_water），供容量审计。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `mem_pool_init(pool,mem,block_size,block_count)` | 初始化池 |
| `mem_pool_alloc(pool)` | 分配一块（O(1)），耗尽返回 NULL |
| `mem_pool_free(pool,ptr)` | 释放一块 |
| `mem_pool_usage(pool)` | 当前占用块数 |
| `mem_pool_high_water(pool)` | 峰值占用块数 |
| `mem_pool_free_count(pool)` | 剩余块数 |
| `mem_pool_verify(pool)` | 校验魔数/链表完整性 |

**池耗尽策略**：返回 NULL（非关键）或触发故障（安全关键，显式失败优于静默降级）。

## 5. 关键流程与时序
- 分配：取空闲链表头 → 摘链 → 返回（全程无系统调用）。
- 释放：回链 → 校验越界/双重释放。
- 单核无锁；多核用自旋锁短临界区（见 concurrency/interrupt-critical）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 安全关键路径 | 静态/池化分配 | malloc | 消除不确定性 |
| 对象池 vs 通用堆 | 按对象类型池化 | 通用堆 | O(1) 且零碎片 |
| 池耗尽 | 显式失败 | 静默降级 | 可被上层处理 |
| 调试 | 块头加魔数+归属信息 | 无 | 越界/双重释放可检测 |

## 7. 性能指标（KPI）
- 分配/释放 O(1)，无遍历。
- 池高水位占用率目标（如 < 80%）。
- 泄漏计数 = 0（运行期/退出时审计）。

## 8. 可靠性设计
- 块头魔数校验：检测越界写、双重释放、野指针。
- 功能安全场景内存保护（如 ECC）。
- 内存耗尽进入降级流程而非崩溃。

## 9. 安全设计
- 分配块内容清零（防信息泄漏残留）。
- 池与块元数据隔离，防应用越界破坏池结构。
- 敏感数据释放前清零（密钥、凭证）。

## 10. 测试与验证策略
- 泄漏检测：退出时统计未释放块。
- 故障注入：模拟池耗尽、越界写，验证检测机制。
- 长时间浸泡测试验证无碎片累积。

## 11. 集成与部署
- 池容量由业务峰值预算表定义，纳入设计评审与容量管理。
