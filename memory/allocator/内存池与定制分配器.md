# 内存池与定制分配器

> 模块目录：`workspace/memory/allocator/` · 接口文件：`include/memory_pool.hpp`

## 1. 模块定位与目标
用 C++ 分配器（Allocator）机制与对象池，为容器和热路径提供确定性、零碎片的分配策略，替代通用 malloc/new。目标是把内存分配从运行期不确定变为可静态预算、可审计。

**边界**：C++ 层，底层复用 C 版 `memory-pool` 的固定块池思想；Rust 对应见 `memory/ownership`。

**服务场景**：网关报文缓冲、流媒体缓冲、AI 推理中间结果、域控实时消息队列。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 确定性 | 分配/释放 O(1)，无碎片累积 |
| 集成 | 通过 std::allocator 接口接入 STL 容器 |
| 约束 | 无异常/无 RTTI（见 foundation/cpp-standard） |
| 约束 | 池容量按业务峰值静态预算 |

## 3. 架构设计

### 3.1 分配器层次
```
业务容器(std::vector/list) ← 定制 allocator(pool_allocator) ← fixed_pool(固定块池)
```

### 3.2 组件职责
| 组件 | 职责 |
|------|------|
| `fixed_pool` | 固定块池底层：free-list、O(1) 分配/释放、高水位统计、归属校验 |
| `pool_allocator<T>` | 满足 Allocator 概念的适配器，把容器内存纳入池 |
| `pool_stats` | 统计：used/high_water/capacity |

### 3.3 池类型
- 固定块池：同尺寸对象，free-list O(1)。
- 分级分配器：多尺寸池组合（本模块可扩展）。
- 栈分配器：作用域内临时分配（可扩展）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `fixed_pool::init(memory,block_size,block_count)` | 初始化 |
| `fixed_pool::allocate()/deallocate()` | O(1) 分配/释放 |
| `fixed_pool::owns(p)` | 归属校验（防双重释放/越界） |
| `fixed_pool::verify()` | 魔数/链表完整性校验 |
| `fixed_pool::stats()` | 统计信息 |
| `pool_allocator<T>::allocate(n)/deallocate(p,n)` | Allocator 接口 |
| `pool_allocator::rebind<U>` | 类型重绑定 |

**语义**：`fixed_pool` 可移动不可复制（见 foundation/move-semantics）；`pool_allocator` 比较基于所属池。

## 5. 关键流程与时序
- allocate：从池取块 → 返回（无锁/短临界区）。
- deallocate：回池 → 校验归属。
- 容器经 `pool_allocator` 隐式调用，避免内部 `new`。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 容器内存 | 定制 allocator 接管 | 默认 new | 避免容器隐式堆分配 |
| 池类型 | 固定块为主 | 分级/栈 | O(1) 零碎片 |
| 多核 | 每核独立池或短临界区 | 全局锁 | 减少锁竞争 |
| 耗尽 | 显式失败/降级 | 静默 | 可预测 |

## 7. 性能指标（KPI）
- allocate/deallocate O(1)。
- 池高水位占用 < 80%。
- 无碎片（长期运行可用块数不衰减）。

## 8. 可靠性设计
- 块头魔数 + 归属信息检测越界/双重释放。
- 池耗尽走降级路径而非崩溃。
- `verify()` 供运行期/测试期完整性检查。

## 9. 安全设计
- 分配块清零防信息泄漏。
- 池元数据与应用数据隔离。

## 10. 测试与验证策略
- 泄漏/越界检测（ASan + 池自检）。
- 浸泡测试验证无碎片。
- 故障注入：池耗尽、越界写。

## 11. 集成与部署
- 池容量预算表纳入容量管理与评审。
