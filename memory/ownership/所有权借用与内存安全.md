# 所有权借用与内存安全

> 模块目录：`workspace/memory/ownership/` · 接口文件：`src/lib.rs`

## 0. 问题定位

- **解决什么问题**：buffer 所有权如何在编译期保证单一所有者，杜绝悬垂、双重释放、use-after-free。
- **边界标准**：
  1. 单一所有权，借用检查编译期强制（硬约束）。
  2. 共享借用用原子/RefCell，无数据竞争（硬约束）。
  3. unsafe 最小化，不绕过所有权语义（硬约束）。
- **系统位置**：环 5；`memory-pool`、`memory-barrier` → 本模块；横切环 6。

## 1. 模块定位与目标
利用 Rust 所有权、借用、生命周期机制在编译期消除内存与数据竞争错误（悬垂指针、双重释放、use-after-free、数据竞争），实现零运行时开销的内存安全。是 Rust 相较 C/C++ 的核心价值。

**边界**：Rust 内存安全抽象；unsafe 边界见 `foundation/rust-unsafe`。

**服务场景**：安全关键模块、并发模块、跨语言互操作（见 foundation/rust-ffi）。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 目标 | 编译期消除内存/并发错误 |
| 约束 | 共享可变状态需显式用锁/原子/Cell |
| 约束 | no_std 环境（见 foundation/rust-nostd） |
| 注意 | 借用检查器约束需在设计期考虑 |

## 3. 架构设计

### 3.1 核心规则
| 规则 | 说明 |
|------|------|
| 所有权 | 每值有唯一所有者 |
| 借用 | 任意时刻：多个共享引用 或 一个可变引用 |
| 生命周期 | 引用有效期由编译器追踪 |
| 移动语义 | 赋值/传参默认移动，源失效 |

### 3.2 共享可变状态
| 机制 | 适用 |
|------|------|
| `&mut T` | 独占可变（无并发） |
| `Mutex<T>`/`RwLock<T>` | 线程间共享 |
| `Atomic*` | 无锁原子（见本模块 `AtomicCounter`） |
| `Cell`/`RefCell` | 单线程内部可变 |
| `Arc<T>` | 多所有者（有计数开销） |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `AtomicCounter` | 线程安全原子计数器（fetch_add/load/store） |
| `Owned<T>` | 唯一所有权对象，移动后源失效（编译器保证） |
| `Exclusive<T>` | 独占可变访问（编译期保证无别名） |
| `cell::SharedCell<T>` | RefCell 内部可变 |

## 5. 关键流程与时序
- 编译期借用检查在代码生成前完成，非法借用即编译错误。
- 运行期无额外检查（零开销，除 RefCell 等运行期借用检查）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 共享可变 | 优先锁/原子 | 裸指针 | 数据竞争编译期杜绝 |
| 所有权 | 默认移动 | 隐式拷贝 | 消除双重释放 |
| 内部可变 | 慎用 RefCell | 滥用 | 引入运行期借用检查 |

## 7. 性能指标（KPI）
- 内存/并发错误编译期归零（unsafe 区除外）。
- 无 GC、无运行期引用计数（除非显式 Arc）。

## 8. 可靠性设计
- 类型系统保证无悬垂/双重释放/数据竞争。
- 生命周期错误在设计期暴露。

## 9. 安全设计
- 编译期内存安全是信息安全的基础（防内存破坏漏洞）。

## 10. 测试与验证策略
- 编译期借用检查即验证。
- 并发代码用 Miri/loom 验证（可选）。
