# 内存模型与存储布局

> 模块目录：`workspace/memory/memory-model/` · 接口文件：`include/memory_model.h`

## 0. 问题定位

- **解决什么问题**：存储类、内存段、对齐、端序、ABI 如何被唯一定义，成为所有内存访问正确性的地基。
- **边界标准**：
  1. 所有内存段起始/大小/属性唯一，无重叠无遗漏（硬约束）。
  2. 对齐与端序假设用静态断言固化，违反即编译错误（硬约束）。
  3. MMIO 区域与普通内存属性严格分离（硬约束）。
- **系统位置**：环 2；`boot/startup` → 本模块 → `memory-barrier`、`kernel/mm`、`kernel/dma`。

## 1. 模块定位与目标
定义 C 程序在目标硬件上的内存组织规则：存储类、内存段、对齐、字节序、ABI 调用约定。是一切驱动、启动代码、跨语言互操作（C/C++/Rust FFI）和内存安全设计的基石。

**边界**：只负责"内存如何布局与寻址"的规则定义，不负责分配策略（见 memory-pool/allocator）与并发访问（见 concurrency）。

**服务场景**：RK3588 驱动、内核模块、FPGA 软核固件、汽车域控 MCU。

## 2. 需求与约束

| 类别 | 要求 |
|------|------|
| 平台 | ARM64 (RK3588)、ARM Cortex-M（域控 MCU）、RISC-V、FPGA 软核 |
| 内存跨度 | KB 级（MCU）到 GB 级（SoC），需统一模型覆盖 |
| 寻址模型 | 无 MMU（MCU 物理寻址）与有 MMU（SoC 虚拟寻址）两套 |
| 强约束 | 栈可能极小（KB 级）；启动代码需精确控制段布局 |
| 对齐 | 结构体成员自然对齐；跨网络/存储才用 packed |

## 3. 架构设计

### 3.1 存储类划分
| 存储类 | 生命周期 | 位置 | 典型用途 |
|--------|----------|------|----------|
| 自动 (auto) | 函数调用期 | 栈 | 局部变量 |
| 寄存器 (register) | 函数调用期 | 寄存器 | 编译器建议 |
| 静态 (static) | 运行期 | .data/.bss | 模块内持久状态 |
| 线程局部 (_Thread_local) | 线程期 | TLS | 每核/每任务私有 |
| 动态 (malloc) | 手动管理 | 堆 | 运行期分配 |

### 3.2 内存段（链接视图）
```
┌──────────────┐ 高地址
│   .stack      │ 栈（向下增长）
├──────────────┤
│   .heap       │ 堆（向上增长）
├──────────────┤
│   .bss        │ 未初始化/零初始化全局变量（不占 ROM）
├──────────────┤
│   .data       │ 已初始化全局/静态变量
├──────────────┤
│   .rodata     │ 只读常量、字符串
├──────────────┤
│   .text       │ 代码
├──────────────┤
│   .vectors    │ 中断向量表（MCU 场景，固定在低地址）
└──────────────┘ 低地址（由链接脚本决定）
```

### 3.3 数据流
- 加载期：镜像（ROM/Flash）→ 拷贝 `.data` → 清零 `.bss` → 跳 `main`。
- 运行期：栈随函数调用伸缩，堆由分配器管理（见 memory-pool）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `__data_start__/__data_end__/__data_load_start__` | 链接脚本导出，`.data` 拷贝边界 |
| `__bss_start__/__bss_end__` | `.bss` 清零边界 |
| `__heap_start__/__heap_end__` | 堆边界 |
| `__stack_top__` | 栈顶 |
| `MM_ALIGN_UP(n,a)` / `MM_ALIGN_DOWN(n,a)` | 向上/向下对齐宏 |
| `MM_STATIC_ASSERT(expr,msg)` | 编译期静态断言，固化布局假设 |
| `mm_startup_check()` | 启动自检（`.bss` 是否清零、`.data` 是否完整） |
| `mm_stack_watermark_init/usage()` | 栈水位检测，防栈溢出 |

## 5. 关键流程与时序
```
上电复位 → 初始化 SP → 拷贝 .data（ROM→RAM）→ 清零 .bss
        → 初始化 C 运行时（可选构造器）→ mm_startup_check() → main()
```
- `.data` 拷贝必须在任何全局变量读之前完成。
- `.bss` 清零必须在 `main` 前完成，否则全局变量初值错误。
- 时序约束：启动到 `main` 时间按平台量化（见 KPI）。

## 6. 设计决策与权衡

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 全局状态存储 | 优先 static 而非 extern | extern | 缩小可见域、便于静态分析 |
| 结构体对齐 | 默认自然对齐 | packed | 访问效率；packed 仅用于硬件寄存器/协议帧 |
| 零初始化 | 依赖 .bss | 显式写 0 | 减小镜像体积（bss 不占 ROM） |
| packed 使用 | 仅协议帧/寄存器 | 全局 | 避免非对齐访问陷阱 |

## 7. 性能指标（KPI）
- 启动到 `main()` 时间：< X µs（按平台定）。
- 镜像体积：`.text + .data` 的 ROM 占用可量化；`.bss` 不占 ROM。
- 非对齐访问次数：应归零（除非有意）。

## 8. 可靠性设计
- `.bss` 未清零、`.data` 未拷贝是启动期 top 缺陷，启动代码带 `mm_startup_check` 自检。
- 栈溢出检测：水位标记（`mm_stack_watermark_*`）+ MPU/栈金丝雀。
- 段重叠校验：链接器 map 文件 + 启动断言。

## 9. 安全设计
- 只读数据放 `.rodata` 并映射为只读页（防误写）。
- 函数指针、跳转表防篡改（结合 MPU/TrustZone）。
- TLS 隔离任务私有数据，避免共享破坏。

## 10. 测试与验证策略
- 链接 map 解析：确认段地址符合预期。
- 栈深度静态分析 + 运行期水位监控。
- 单元测试覆盖各种对齐/端序组合。

## 11. 集成与部署
- 链接脚本纳入版本管理，禁止手工改默认布局。
- CI 中生成并比对 `.map`，段地址漂移即告警。
