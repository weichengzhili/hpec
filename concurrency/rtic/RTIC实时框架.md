# RTIC 实时框架

> 模块目录：`workspace/concurrency/rtic/` · 接口文件：`src/lib.rs`

## 1. 模块定位与目标
用 RTIC（Real-Time Interrupt-driven Concurrency）构建基于优先级抢占的硬实时应用：任务即中断处理函数，资源访问由框架静态分析保证无数据竞争，提供确定性调度与优先级上限分析。

**服务场景**：汽车域控实时控制、工业机器人运动/伺服控制、电机控制等强实时任务。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 硬实时 | 基于中断优先级抢占 |
| 安全 | 资源竞争编译期杜绝 |
| 约束 | 任务优先级静态定义，运行期不变 |
| 上限 | 优先级上限（ceiling）保证无死锁 |

## 3. 架构设计

### 3.1 核心概念
| 概念 | 说明 |
|------|------|
| 任务 (task) | 绑定硬件中断或软件任务，带优先级 |
| 资源 (resource) | 任务间共享数据 |
| 优先级上限 | 资源访问使用最高任务优先级 |
| 抢占 | 高优先级任务抢占低优先级 |

### 3.2 保证机制
- 框架静态分析资源访问，拒绝数据竞争。
- 优先级天花板协议（ICPP）防止优先级反转与死锁。
- 生成确定性调度代码，零动态内存。

## 4. 接口设计（编程模型约定）

| 接口 | 说明 |
|------|------|
| `#[init]` | 初始化任务：配置外设、共享资源 |
| `#[task(priority=n, shared=[res])]` | 定义任务 |
| `#[idle]` | 空闲任务 |
| `Shared<C,T>::lock()` | 资源临界访问（天花板优先级 C） |
| `Priority` | 优先级类型（编译期静态） |

## 5. 关键流程与时序
```
中断触发 → RTIC 调度 → 按优先级执行任务 → 资源按天花板协议加锁/解锁 → 完成
```
高优先级任务随时抢占低优先级。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 调度 | 中断优先级抢占 | 协作式 | 硬实时确定性 |
| 资源 | 静态分析 | 运行时锁 | 编译期杜绝竞争 |
| 协议 | 优先级天花板 | 继承 | 防反转/死锁 |
| 内存 | 零动态分配 | 堆 | 确定性 |

## 7. 性能指标（KPI）
- 任务切换/抢占延迟可量化（时钟周期级）。
- 中断响应延迟符合实时要求。
- 数据竞争编译期 = 0。

## 8. 可靠性设计
- 静态分析保证无竞争、无死锁。
- 优先级上限分析保证有界阻塞。

## 9. 安全设计
- 资源所有权类型安全，无共享破坏。

## 10. 测试与验证策略
- 调度正确性测试。
- 最坏情况执行时间（WCET）分析。

## 11. 集成与部署
- RTIC 版本锁定，任务优先级纳入配置管理。
