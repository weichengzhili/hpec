# 异步嵌入式与执行器

> 模块目录：`workspace/concurrency/async/` · 接口文件：`src/lib.rs`

## 1. 模块定位与目标
用 async/await 构建协作式并发的嵌入式应用：自定义执行器、无阻塞异步原语（定时器、I/O 等待），在单核/多核上以低开销实现多任务并发，替代手写状态机。

**边界**：Rust async 并发；硬实时抢占用 `concurrency/rtic`。

**服务场景**：网关协议处理、IoT 边缘多连接、驱动事件循环。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 无 std | 需基于 core 的自定义执行器 |
| 约束 | Future 需可静态分配，避免堆 |
| 确定性 | 协作式调度，无抢占 |

## 3. 架构设计

### 3.1 异步组件
| 组件 | 说明 |
|------|------|
| `Future` | 惰性异步计算 |
| `Executor` | 轮询就绪 Future |
| `Reactor`/Waker | 唤醒机制，连接中断/事件 |
| 异步原语 | 定时器、I/O 等待 |

### 3.2 执行器模型
- 单核：循环 poll 任务，事件驱动唤醒。
- 多核：每核执行器或任务分配。
- 常用嵌入式执行器：embassy（tokio 需 std，一般不用于裸机）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `TimerFuture` / `sleep_ms()` | 异步休眠（定时器驱动） |
| `Executor::new/spawn/run` | 执行器（生成/运行任务） |
| `AsyncRead/AsyncWrite` | 异步 IO trait（对应 embedded-hal-async） |
| `Reactor::register_waker/wake_all` | 唤醒机制 |

## 5. 关键流程与时序
```
执行器 poll Future → Future 未就绪则注册 Waker → 事件触发 → Waker 唤醒
                  → 执行器再次 poll
```
协作式：任务主动让出（await）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 执行器 | 嵌入式轻量执行器 | tokio | 无 std、低开销 |
| 分配 | 静态 Future（避免堆） | 堆分配 | 确定性 |
| 调度 | 协作式 | 抢占式 | 简单、确定性 |
| 硬实时 | 用 RTIC | async | async 不适合强实时抢占 |

## 7. 性能指标（KPI）
- 任务切换开销低（无栈切换，栈内状态机）。
- 内存占用可静态预算（无堆 async）。

## 8. 可靠性设计
- 任务 panic 隔离与恢复。
- 定时器超时兜底防卡死。

## 9. 安全设计
- async 数据所有权类型安全，无共享竞争。

## 10. 测试与验证策略
- 执行器单元测试（模拟时钟/事件）。
- 多任务并发压力测试。
