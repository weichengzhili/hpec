# 状态机与任务设计

> 模块目录：`workspace/concurrency/fsm/` · 接口文件：`include/fsm.h`

## 0. 问题定位

- **解决什么问题**：并发状态如何显式建模为表驱动状态机，避免隐式状态和竞态。
- **边界标准**：
  1. 状态转移表驱动，无隐式状态变量（硬约束）。
  2. 非法状态转移被拒绝（编译期或运行时）（硬约束）。
  3. 事件队列满/溢出有明确处理（硬约束）。
- **系统位置**：环 6；`interrupt-critical` → 本模块 → `scheduler`。

## 1. 模块定位与目标
建立事件驱动的状态机与任务划分方法论，用于协议处理、设备控制、流程编排等有明确状态转换的逻辑。目标是让复杂控制逻辑可读、可测、可证明状态覆盖。

**边界**：C 语言表驱动状态机；C++ 版见 `concurrency/fsm-event`。

**服务场景**：网关协议状态机（Modbus/OPC-UA）、域控模式管理、机器人控制流程、充电桩/设备状态管理。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 确定性 | 状态转换可枚举、可覆盖测试 |
| 并发 | 事件来自中断/多任务，需队列化 |
| 可维护 | 新增状态/事件不影响既有逻辑 |
| 约束 | 禁止巨型 switch 散落各处的非法转换 |

## 3. 架构设计

### 3.1 状态机类型选型
| 类型 | 适用 | 特点 |
|------|------|------|
| 表驱动状态机 | 状态/事件多、规则化 | 转换表集中，易验证 |
| switch-case 状态机 | 简单、状态少 | 直观但易膨胀 |
| 分层状态机 (HSM) | 复杂层次状态 | 支持继承，减少重复 |
| 事件队列驱动 | 实时系统 | 事件解耦、可排队 |

### 3.2 事件驱动模型
```
事件源(中断/任务/定时器) → 事件队列(fsm_event_queue) → 状态机调度(fsm_dispatch) → 动作/状态转换
```

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `fsm_state_t/fsm_event_t` | 状态/事件类型 |
| `fsm_action_t` | 动作函数（返回新状态） |
| `fsm_transition_t` | 转换表项（from/event/to/action） |
| `fsm_init()` | 初始化（表、初始状态、钩子） |
| `fsm_dispatch()` | 事件分发（查表，非法转换上报） |
| `fsm_current()/fsm_can_transition()` | 查询 |
| `fsm_event_queue_*` | 事件队列（push/pop） |

## 5. 关键流程与时序
```
取事件 → 查转换表 → 匹配则执行动作并切换状态（先 on_exit 再 on_entry）
        → 不匹配则记非法转换并上报
```
非法转换必须被检测（防御式），不能静默忽略。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 转换规则 | 表驱动 | switch | 集中、可审计、易测 |
| 事件传递 | 队列化 | 直接调用 | 解耦中断与处理 |
| 非法转换 | 显式检测上报 | 静默忽略 | 可靠性与可诊断 |
| 层次状态 | 复杂场景用 HSM | 扁平 | 减少状态重复 |

## 7. 性能指标（KPI）
- 状态转换全路径覆盖率 100%。
- 事件处理延迟可量化、有界。
- 状态机执行无阻塞、无动态内存。

## 8. 可靠性设计
- 非法事件/状态检测与告警。
- 超时状态（看门狗事件）处理卡死。
- 状态转换日志可追溯。

## 9. 安全设计
- 安全关键状态机独立、可形式化验证。
- 状态机数据隔离，防越界篡改转换表。

## 10. 测试与验证策略
- 全状态×全事件转换覆盖测试。
- 形式化/模型检验（安全关键场景）。
- 随机事件流浸泡测试。

## 11. 集成与部署
- 状态机框架作为通用组件复用，转换表配置化。
