# 状态机与事件驱动

> 模块目录：`workspace/concurrency/fsm-event/` · 接口文件：`include/fsm.hpp`

## 0. 问题定位

- **解决什么问题**：强类型状态机如何用类型系统保证状态转移安全。
- **边界标准**：
  1. 状态/事件强类型，非法转移编译错误（硬约束）。
  2. 无动态分配，适合嵌入式（硬约束）。
  3. 状态与事件可静态枚举（硬约束）。
- **系统位置**：环 6；`interrupt-critical` → 本模块。

## 1. 模块定位与目标
用 C++ 类型系统构建类型安全、可扩展的状态机与事件驱动框架，替代散落的 switch-case。支持分层状态、事件队列、编译期非法转换检测。是 C 语言状态机（concurrency/fsm）的类型安全升级版。

**服务场景**：协议状态机、设备模式管理、机器人控制流程、充电/流程编排。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 类型安全 | 状态/事件为强类型（enum class），禁止隐式混用 |
| 可扩展 | 新增状态/事件不影响既有逻辑 |
| 约束 | 热路径零虚函数开销（模板/静态分派） |
| 约束 | 无异常环境（见 foundation/cpp-standard） |

## 3. 架构设计

### 3.1 状态机框架
| 组件 | 说明 |
|------|------|
| `State/Event` | 强类型 enum class |
| `state_machine<State,Event,NTrans>` | 表驱动引擎 |
| `transition` | 转换表项（from/event/to/action） |
| `on_entry/on_exit` | 进入/退出钩子（std::function） |

### 3.2 分层状态机（HSM）
复杂场景用分层状态机，子状态继承父状态行为，减少重复转换。可用状态模式 + 继承，或模板库（如 SML）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `state_machine::init(initial, table)` | 初始化 |
| `state_machine::dispatch(ev)` | 事件分发（非法转换上报） |
| `state_machine::current()/can(ev)` | 查询 |
| `event_queue<Event>` | 类型安全事件队列 |

**约束**：`State`/`Event` 必须为 enum class（`static_assert` 保证）。

## 5. 关键流程与时序
```
事件入队 → 分发到当前状态 → 查转换表 → 执行退出动作(on_exit)
        → 切换状态 → 执行进入动作(on_entry) → 执行转换动作
```

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 状态类型 | enum class | int 宏 | 类型安全，防误用 |
| 转换 | 表驱动 | switch | 集中可审计 |
| 分层 | 复杂场景用 HSM | 扁平 | 减少重复 |
| 热路径 | 模板/静态分派 | 虚函数 | 零虚调用 |

## 7. 性能指标（KPI）
- 状态转换全路径覆盖 100%。
- 分发 O(1) 或小常数，无动态内存。

## 8. 可靠性设计
- 非法转换显式检测上报。
- 超时事件防卡死。
- 状态转换日志可追溯。

## 9. 安全设计
- 安全关键状态机独立、可形式化验证。
- 转换表只读保护。

## 10. 测试与验证策略
- 全状态×全事件覆盖测试。
- 随机事件流浸泡测试。
- 模型检验（安全关键）。

## 11. 集成与部署
- 状态机框架作为通用组件，转换配置化。
