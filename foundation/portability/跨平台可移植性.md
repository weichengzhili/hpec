# 跨平台可移植性

> 模块目录：`workspace/foundation/portability/` · 接口文件：`include/portability.h`

## 1. 模块定位与目标
建立跨平台（不同架构/编译器/OS）一致的代码写法：固定宽度类型、字节序处理、平台差异抽象、条件编译管理。目标是同一份业务逻辑可运行于 RK3588、MCU、FPGA 软核与主机仿真。

**服务场景**：工业网关多平台、协议栈移植、驱动可复用、主机仿真测试。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 架构 | ARM64、ARM Cortex-M、RISC-V、x86(仿真) |
| 端序 | 大端/小端平台均需正确处理 |
| 编译器 | GCC、Clang、ARMCC、IAR 差异需隔离 |
| 约束 | 减少平台相关代码散落，集中在 HAL/抽象层 |

## 3. 架构设计

### 3.1 可移植性分层
```
┌──────────────────────────┐
│  业务逻辑（平台无关）      │
├──────────────────────────┤
│  平台抽象层 (HAL/PAL)     │ 统一接口
├──────────────────────────┤
│  平台实现（RK3588/MCU/x86）│
└──────────────────────────┘
```

### 3.2 关键可移植性要素
| 要素 | 方案 |
|------|------|
| 整数类型 | 固定宽度 stdint.h |
| 字节序 | 网络字节序统一 + hton/ntoh |
| 对齐 | packed 并注释原因 |
| 大小 | sizeof 而非假设 |
| 断言 | 编译期静态断言 |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `port_htons/ntohs/htonl/ntohl` | 字节序转换 |
| `hal_time_ms()/time_us()/delay_ms()/delay_us()` | 时间 HAL |
| `hal_gpio_set/get/config()` | GPIO HAL |
| `hal_uart_send/recv()` | UART HAL |
| `hal_platform_name()/id()` | 平台信息 |

## 5. 关键流程与时序
协议帧序列化/反序列化必须显式处理字节序与对齐，避免结构体直接强转（`*(struct*)buf`）导致的端序/对齐/填充缺陷。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 类型 | 固定宽度 | int | 消除位宽差异 |
| 端序 | 显式转换 | 强转 | 避免陷阱 |
| 条件编译 | 集中在平台层 | 散落 | 业务清晰 |
| 仿真 | 平台抽象支持 x86 | 仅目标机 | 加速开发测试 |

## 7. 性能指标（KPI）
- 平台相关代码占比 < 10%。
- 一份业务代码零改动跨平台编译通过。

## 8. 可靠性设计
- 编译期静态断言保证类型/结构体布局假设。
- 字节序测试在两种端序环境回归。

## 9. 安全设计
- 反序列化长度校验，防越界。

## 10. 测试与验证策略
- 跨平台 CI 矩阵编译 + 同一套单测。
- 字节序/对齐专项测试。

## 11. 集成与部署
- 平台抽象接口版本化，平台实现单独管理。

## 12. 参考资料
- C99/C11 stdint.h 与静态断言。
- 各编译器可移植性差异文档。
