# 调试与工具链

> 模块目录：`workspace/foundation/debug-log/` · 接口文件：`include/debug_log.h`

## 0. 问题定位

- **解决什么问题**：日志分级/断言/崩溃转储如何统一，不拖累性能。
- **边界标准**：
  1. 日志分级，可编译期裁剪（硬约束）。
  2. 断言在生产环境有明确策略（禁用/降级/上报）（硬约束）。
  3. 崩溃转储格式稳定，可解析（硬约束）。
- **系统位置**：环 9；`kernel/debug` → 本模块。

## 1. 模块定位与目标
建立完整的嵌入式 C 调试与工具链体系：交叉编译、构建系统、在线调试（JTAG/SWD）、日志与追踪、性能分析。目标是让问题可定位、可复现、可量化。

**服务场景**：所有平台（RK3588、MCU、FPGA 软核）的开发与排障。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 工具链 | 交叉编译器（aarch64/arm-none-eabi/riscv） |
| 调试 | 硬件调试器（J-Link/OpenOCD）、内核 kgdb |
| 构建 | 统一构建系统（CMake/Make/Bazel） |
| 约束 | 日志在实时/安全场景需低开销、可关断 |

## 3. 架构设计

### 3.1 工具链栈
```
编辑器/IDE → 构建系统 → 交叉编译器 → 链接器 → 烧录/调试
                                    ↓
                         静态分析 + 单测（CI）
```

### 3.2 日志分级体系
| 级别 | 用途 | 生产环境 |
|------|------|----------|
| FATAL | 致命错误 | 开启 |
| ERROR | 错误 | 开启 |
| WARN | 告警 | 开启 |
| INFO | 关键信息 | 按需 |
| DEBUG | 调试详情 | 关闭 |
| TRACE | 逐函数追踪 | 关闭 |

### 3.3 调试手段
- 在线调试：断点、单步、内存/寄存器观察。
- 日志：分级、环形缓冲、时间戳、线程/核 ID。
- 追踪：函数级追踪、事件记录。
- 转储：崩溃时寄存器+栈转储（core dump/异常帧）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `log_set_level/get_level/write()` | 日志分级接口 |
| `DEBUG_ASSERT(cond)` | 断言（触发转储） |
| `crash_frame_t` | 崩溃帧（PC/LR/SP/寄存器） |
| `debug_crash_dump()/store_to_nvm()` | 崩溃转储 |
| `trace_event()/trace_dump()` | 事件追踪（环形缓冲） |

## 5. 关键流程与时序
崩溃处理流程：异常捕获 → 记录 PC/LR/寄存器/栈 → 转储到非易失存储 → 复位。崩溃处理本身极简、可重入。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 日志 | 编译期裁剪 + 运行期分级 | 全开 | 生产零开销 |
| 日志实现 | 环形缓冲 + 异步输出 | 同步输出 | 不阻塞实时路径 |
| 调试 | JTAG/SWD 为主 | 纯日志 | 硬故障场景必需 |
| 构建 | 统一 CMake | 各自 | 跨团队一致 |

## 7. 性能指标（KPI）
- 日志关闭时开销 ≈ 0（编译期剔除）。
- 崩溃转储时间 < 阈值，转储完整率 100%。

## 8. 可靠性设计
- 看门狗 + 崩溃转储联动，定位复位原因。
- 日志环缓冲防溢出覆盖，保留最近记录。

## 9. 安全设计
- 生产固件禁止开放调试口（或需安全解锁）。
- 日志脱敏，不输出密钥/凭证。

## 10. 测试与验证策略
- 断点/单步回归验证调试链路。
- 崩溃注入验证转储完整性。

## 11. 集成与部署
- 工具链版本固化，纳入容器化构建环境。
