# 模板元编程

> 模块目录：`workspace/foundation/templates/` · 接口文件：`include/type_traits.hpp`

## 0. 问题定位

- **解决什么问题**：如何用类型系统消除单位错误和类型混用。
- **边界标准**：
  1. 强类型单位/萃取在编译期校验，非法类型编译错误。
- **系统位置**：环 3。

## 1. 模块定位与目标
用模板实现类型安全、静态多态、编译期分派，替代运行时虚函数与 void* 类型擦除，做到"零开销抽象"。目标是让驱动框架、容器、协议编解码在保持类型安全的同时无运行时代价。

**服务场景**：设备驱动框架、通用容器（受限环境）、协议编解码、单元类型系统（长度/频率/地址）。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 约束 | 模板不产生虚函数、无运行时 RTTI 依赖 |
| 风险 | 模板膨胀（代码体积）、编译时间、错误信息难读 |
| 原则 | 只在消除重复/类型不安全处使用，不过度 |

## 3. 架构设计

### 3.1 技术手段
| 手段 | 用途 |
|------|------|
| 模板类/函数 | 泛型复用 |
| 模板特化/偏特化 | 按类型定制 |
| 类型萃取 (type traits) | 类型属性判断与变换 |
| SFINAE / requires(C++20) | 约束与重载分派 |
| CRTP | 静态多态、基类复用 |
| 变参模板 | 通用接口、tuple |

### 3.2 CRTP 静态多态
基类模板接收派生类型作为模板参数（`crtp_base<Derived>`），基类可调用派生类方法而无需虚函数。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `strong_type<T,Tag>` | 强类型单位（长度/频率/电压/电流） |
| `length_mm/freq_hz/volt_t/ampere_t` | 单位类型别名 |
| `crtp_base<Derived>` | CRTP 静态多态基类 |
| `remove_cvref_t` / `constant_t` | 类型工具 |

## 5. 关键流程与时序
编译期展开：模板实例化 → 类型推导 → 分派选择 → 生成专用代码。运行期与手写专用代码等价（零开销）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 多态 | 优先 CRTP/模板 | 虚函数 | 实时场景零虚函数开销 |
| 约束 | C++20 concepts | SFINAE | 提升可读性与错误信息 |
| 单位 | 强类型单位 | 裸数值 | 编译期杜绝量纲错误 |
| 复杂度 | 控制模板深度 | 过度抽象 | 可维护性与编译时间 |

## 7. 性能指标（KPI）
- 运行时与手写非泛型代码等价（反汇编验证无虚调用）。
- 代码体积增量可控。

## 8. 可靠性设计
- 用 static_assert + concepts 把非法用法变成编译错误。
- 类型安全消除 void* 导致的运行时类型错误。

## 9. 安全设计
- 强类型避免隐式转换导致的安全隐患（如单位错误）。
- 类型擦除接口（如需）做边界校验。

## 10. 测试与验证策略
- 编译期测试（static_assert、类型特性）。
- 反汇编抽查确认无虚调用、无 RTTI。

## 11. 集成与部署
- 模板代码集中在头文件，注意依赖管理。
