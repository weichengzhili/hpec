# RAII 与资源管理

> 模块目录：`workspace/foundation/raii/` · 接口文件：`include/raii.hpp`

## 1. 模块定位与目标
用 RAII（资源获取即初始化）原则管理文件句柄、外设、锁、内存、定时器等资源，使资源在作用域结束时自动、确定地释放，避免泄漏与双重释放，即使发生错误路径也能保证清理。

**服务场景**：所有 C++ 嵌入式模块——驱动句柄、锁、DMA 缓冲、设备打开/关闭、定时器。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 确定性 | 释放时机可预测（析构），不依赖 GC |
| 异常安全 | 无异常模式下也要保证清理 |
| 约束 | 禁止裸 new/delete 散落，统一 RAII 封装 |

## 3. 架构设计

### 3.1 RAII 封装对象
| 资源 | RAII 封装 | 构造 | 析构 |
|------|-----------|------|------|
| 内存 | 智能指针/容器 | 分配 | 释放 |
| 文件 | 文件对象 | open | close |
| 外设 | 设备对象 | init | deinit |
| 锁 | 锁守卫 | lock | unlock |
| DMA | 缓冲对象 | 映射 | 解映射 |
| 定时器 | 定时器对象 | 启动 | 取消 |

### 3.2 所有权模型
| 模型 | 适用 |
|------|------|
| 独占 (unique_ptr) | 唯一所有权，可移动不可复制 |
| 共享 (shared_ptr) | 多处引用，慎用（原子计数开销） |
| 栈对象 | 作用域生命周期（最推荐） |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `scoped_handle<Handle,Invalid,Release>` | 通用 RAII 句柄封装 |
| `lock_guard<Lockable>` | 锁守卫（作用域自动解锁） |
| `scope_exit<Fn>` / `make_scope_exit` | 作用域退出动作（defer 语义） |

## 5. 关键流程与时序
构造获取资源 → 作用域内使用 → 析构自动释放。错误路径（提前 return）由析构兜底，无需手动 goto cleanup。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 所有权 | 栈对象 + unique_ptr | 裸指针 | 确定性、零/低开销 |
| shared_ptr | 受限使用 | 广泛 | 原子计数多核有开销 |
| 释放 | 析构兜底 | 手动 | 消除泄漏路径 |
| 句柄 | RAII 封装 | 裸句柄 | 防忘记 close |

## 7. 性能指标（KPI）
- 资源泄漏计数 = 0。
- 锁守卫等零开销（内联后与手动 lock/unlock 等价）。

## 8. 可靠性设计
- 析构幂等（重复释放安全）。
- 对象移动后源对象置空，防双重释放。

## 9. 安全设计
- 敏感资源（密钥缓冲）析构清零。
- 禁止悬空指针：所有权清晰 + 智能指针。

## 10. 测试与验证策略
- 泄漏检测（Valgrind/ASan/LSan）。
- 异常/错误路径资源释放测试。

## 11. 集成与部署
