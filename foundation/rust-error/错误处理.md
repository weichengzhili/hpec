# 错误处理

> 模块目录：`workspace/foundation/rust-error/` · 接口文件：`src/lib.rs`

## 1. 模块定位与目标
建立嵌入式 Rust 错误处理体系：用 Result 类型、错误枚举、thiserror/defmt 与 panic 策略，保证错误显式传播、可诊断、可恢复，避免错误被吞没。

**服务场景**：所有 Rust 嵌入式模块（与 foundation/result 对应）。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 无异常 | Rust 无异常，用 Result 显式传播 |
| 轻量 | 无 std 环境错误类型需 no_std 兼容 |
| panic | 需自定义 panic_handler 与策略 |

## 3. 架构设计

### 3.1 错误处理层次
| 机制 | 用途 |
|------|------|
| Result<T,E> | 可恢复错误 |
| panic! | 不可恢复错误（bug） |
| Option<T> | 可能缺失的值 |
| defmt/log | 错误日志与格式化 |

### 3.2 错误类型设计
- 错误枚举：分层编码（`Error` 枚举）。
- 用 thiserror 派生（std 场景）或手写（no_std）。
- 用 defmt 提供轻量格式化。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `Error` | 错误枚举（分层编码，实现 Display） |
| `Result<T>` | 通用结果类型别名 |
| `ok_or_param()` | 便捷错误构造 |

## 5. 关键流程与时序
错误在产生点构造 → `?` 传播 → 边界集中处理（重试/降级/上报）。panic 进入 panic_handler 记录后复位。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 错误传播 | Result + ? | 异常 | 显式、类型安全 |
| 不可恢复 | panic + handler | 忽略 | 复位到安全态 |
| 日志 | defmt | println | 轻量、高效格式化 |

## 7. 性能指标（KPI）
- 错误路径零异常开销。
- 错误覆盖率 100%（无吞错）。

## 8. 可靠性设计
- panic 复位保证系统回到已知状态。
- 错误上下文记录便于诊断。

## 9. 安全设计
- 错误信息脱敏，不泄露内部细节。

## 10. 测试与验证策略
- 每条错误路径单测。
- panic 注入验证恢复。

## 11. 集成与部署
- 错误码集中管理，避免冲突。
