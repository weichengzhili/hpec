# MISRA-C 与功能安全编码

> 模块目录：`workspace/foundation/misra/` · 接口文件：`include/misra_safety.h`

## 0. 问题定位

- **解决什么问题**：如何用 MISRA-C 规则约束安全关键代码。
- **边界标准**：
  1. 规则可静态检查，安全关键路径零违例。
- **系统位置**：环 3、环 8。

## 1. 模块定位与目标
建立面向功能安全（ISO 26262 / IEC 61508）的 C 编码规范与静态分析合规体系，消除 C 语言的未定义行为与易错构造，使代码可证明、可审计。是汽车域控、工业机器人安全功能的强制要求。

**服务场景**：汽车域控（ASIL）、工业机器人（安全功能）、网关（高可用）。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 标准 | MISRA-C:2012 及适用修订 |
| 安全等级 | ISO 26262 ASIL-A/B/C/D、IEC 61508 SIL |
| 工具 | 静态分析工具 + 编译器告警全开 |
| 强制 | 安全关键代码零偏离，或偏离需评审并记录 |

## 3. 架构设计

### 3.1 规则分级
| 类别 | 说明 | 关键规则示例 |
|------|------|--------------|
| 强制 (Mandatory) | 不可偏离 | 禁止未定义行为、隐式类型转换陷阱 |
| 必需 (Required) | 偏离需正式评审 | 动态内存、函数指针限制 |
| 建议 (Advisory) | 推荐遵守 | 可读性、命名 |

### 3.2 合规流程
编码 → 静态分析（MISRA 检查）→ 偏离评审 → 单元/集成测试 → 覆盖率达标 → 安全评审签字。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `u8_t~s64_t/addr_t` | 显式固定宽度类型 |
| `safety_ret_t` | 安全返回码（分层编码） |
| `SAFETY_ASSERT(cond)` | 防御式断言（生产可关断） |
| `safety_assert_fail()` | 断言失败处理 |
| `safety_watchdog_kick()/monitor_report()` | 看门狗/安全监控 |

## 5. 关键流程与时序
功能安全开发遵循 V 模型：需求 → 架构 → 详细设计 → 实现 → 单元测试 → 集成 → 系统测试 → 验证。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 动态内存 | 安全关键路径禁用 | 允许 | 消除 malloc 不确定性 |
| 函数指针 | 受限使用 | 自由 | 便于控制流分析 |
| 类型 | 强制显式类型 | 隐式 | 消除隐式转换风险 |
| 递归 | 禁用 | 允许 | 栈使用可静态确定 |

## 7. 性能指标（KPI）
- MISRA 合规率目标 100%（偏离项有记录）。
- 覆盖率按 ASIL 等级达标（ASIL-D MC/DC）。
- 静态分析告警清零。

## 8. 可靠性设计
- 防御式编程：输入校验、返回值检查、错误处理。
- 看门狗与安全监控。

## 9. 安全设计
- 与信息安全（ISO 21434）交叉：内存安全、防注入、防侧信道。

## 10. 测试与验证策略
- 静态分析：PC-lint Plus / Coverity / cppcheck。
- 单元测试 + MC/DC 覆盖率（ASIL-D）。
- 故障注入测试（FIT）。

## 11. 集成与部署
- 规范版本化，工具链配置纳入仓库。
