# 移动语义与性能

> 模块目录：`workspace/foundation/move-semantics/` · 接口文件：`include/move_buffer.hpp`

## 1. 模块定位与目标
利用移动语义消除不必要的深拷贝，实现零拷贝传递大缓冲/大对象，降低热路径开销，同时避免隐式复制导致的性能与内存问题。目标是让高性能代码既安全又高效。

**服务场景**：流媒体缓冲、协议大报文、AI 推理中间张量、容器扩容。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 目标 | 热路径零深拷贝 |
| 约束 | 移动后源对象须处于合法可析构状态 |
| 注意 | 隐式复制是性能隐患，需显式控制 |

## 3. 架构设计

### 3.1 拷贝/移动语义
| 语义 | 说明 |
|------|------|
| 拷贝构造/赋值 | 深拷贝，开销大 |
| 移动构造/赋值 | 转移内部资源（指针/句柄），零拷贝 |
| 五法则 | 析构/拷贝/移动语义需一致定义 |

### 3.2 应用模式
- 缓冲对象（大 vector/array）移动传递而非拷贝。
- 容器扩容用移动避免元素深拷贝。
- 函数返回值优化（RVO）+ 移动兜底。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `buffer(size)` | 分配缓冲 |
| `buffer(buffer&&)` / `operator=` | 移动（转移所有权，源置空） |
| `clone()` | 显式深拷贝（按需） |
| `swap()` | 交换 |
| `data()/size()/empty()` | 访问 |

**语义**：拷贝构造/赋值 `= delete`，禁止隐式深拷贝。

## 5. 关键流程与时序
移动构造：转移资源指针 → 源对象指针置空 → 源对象仍可析构（析构不释放已转移资源）。避免移动后源对象被继续使用（use-after-move）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 大缓冲 | 移动传递 | 拷贝 | 零拷贝 |
| 拷贝 | 显式 =delete | 隐式 | 防隐式深拷贝 |
| 返回值 | RVO + 移动 | 拷贝 | 无额外开销 |
| 源对象 | 移动后置空 | 保留 | 析构安全 |

## 7. 性能指标（KPI）
- 热路径深拷贝次数 = 0。
- 大缓冲传递零额外分配。

## 8. 可靠性设计
- 移动后源对象置空，保证析构安全。
- 避免 use-after-move（静态分析 + 编码约定）。

## 9. 安全设计
- 移动后敏感数据清零，防残留。

## 10. 测试与验证策略
- 拷贝/移动计数测试验证零拷贝。
- use-after-move 静态分析（clang-tidy）。
