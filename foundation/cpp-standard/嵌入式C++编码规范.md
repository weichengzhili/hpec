# 嵌入式 C++ 编码规范

> 模块目录：`workspace/foundation/cpp-standard/` · 接口文件：`include/types.hpp`

## 1. 模块定位与目标
定义嵌入式/安全场景下 C++ 的安全子集与编码规范（类 AUTOSAR C++14 / MISRA C++），明确禁用特性、允许特性与强制规则，使代码可静态分析、可证明、可移植。

**服务场景**：汽车域控（AUTOSAR 风格）、机器人安全功能、网关高可用。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 标准 | 以 AUTOSAR C++14 / MISRA C++ 为基准 |
| 禁用 | 异常、RTTI、裸 new/delete、未约束模板 |
| 约束 | 兼容 -fno-exceptions -fno-rtti |

## 3. 架构设计

### 3.1 特性分级
| 级别 | 特性 | 说明 |
|------|------|------|
| 禁止 | 异常、RTTI、动态类型、未约束递归 | 不确定/开销 |
| 受限 | 虚函数、多重继承、模板元编程 | 需评审 |
| 推荐 | RAII、强类型、constexpr、Result | 安全高效 |
| 强制 | 固定宽度类型、显式构造、初始化 | 确定性 |

### 3.2 规则体系
- 类型安全：enum class、显式类型转换、固定宽度类型。
- 资源：RAII、禁止裸指针所有权。
- 并发：锁守卫、原子操作。
- 命名与结构：统一命名、单一职责。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `u8/s8/u16/s16/u32/s32/u64/s64/usize` | 固定宽度类型别名 |
| `status` | 统一状态枚举 |
| `CPPSTD_HAS_EXCEPTIONS` | 异常编译检测宏 |

## 5. 关键流程与时序
编码 → clang-tidy/AUTOSAR 检查 → 偏离评审 → 合入。规则与工具配置版本化。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 异常 | 禁用 | 启用 | 实时确定性 |
| 动态内存 | 受限 | 自由 | 确定性（见 memory/allocator） |
| 虚函数 | 受限 | 广泛 | 实时场景零开销偏好 |
| 模板 | 约束使用 | 无限制 | 控制代码膨胀 |

## 7. 性能指标（KPI）
- 静态分析告警清零（偏离项有记录）。
- 覆盖率按安全等级达标。

## 8. 可靠性设计
- 规则聚焦消除未定义行为与资源泄漏。

## 9. 安全设计
- 与信息安全规范交叉（内存安全、防注入）。

## 10. 测试与验证策略
- clang-tidy + 静态分析 + 覆盖率。

## 11. 集成与部署
- 规范与工具配置版本化、跨团队一致。
