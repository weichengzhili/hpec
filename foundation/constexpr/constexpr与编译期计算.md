# constexpr 与编译期计算

> 模块目录：`workspace/foundation/constexpr/` · 接口文件：`include/constexpr_utils.hpp`

## 0. 问题定位

- **解决什么问题**：查表/CRC/位布局如何在编译期完成，消除运行期开销。
- **边界标准**：
  1. 所有计算编译期求值（`static_assert` 验证），无运行期成本。
- **系统位置**：环 3、环 5。

## 1. 模块定位与目标
利用 C++17/20 的 constexpr 能力，将可在编译期确定的计算（查找表、CRC、配置解析、常量折叠）提前到编译期，消除运行时开销与初始化成本，同时用编译器保证正确性。

**服务场景**：CRC/校验表、协议常量、寄存器字段布局、滤波器系数、外设分频系数。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 标准 | C++17 起（C++20 更完整） |
| 约束 | 编译期计算不可动态内存（C++20 前）、不可 IO |
| 收益 | 运行时零开销、启动零初始化、错误编译期暴露 |

## 3. 架构设计

### 3.1 适用对象
| 对象 | 示例 |
|------|------|
| constexpr 变量 | 常量表、配置项 |
| constexpr 函数 | 纯函数计算（CRC、掩码、位布局） |
| constexpr 构造函数 | 编译期构造复杂类型 |
| constexpr if | 编译期分支裁剪 |
| consteval (C++20) | 强制编译期求值 |

### 3.2 设计模式
- **查表生成**：CRC 表、正弦表用 constexpr 函数编译期生成。
- **寄存器布局**：字段偏移/掩码由 constexpr 计算（`reg_field`）。
- **if constexpr 裁剪**：按模板参数编译期选择实现。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `crc32_table_entry(i)` | 编译期 CRC 查表项 |
| `reg_field{mask/get/set}` | 编译期位布局计算 |
| `factorial(n)` / `lut_generate(idx)` | 编译期纯函数 |
| `is_pow2(v)` | if constexpr 分支裁剪示例 |

## 5. 关键流程与时序
编译期：模板实例化 → constexpr 求值 → 常量写入只读段（.rodata）。运行期：直接读取，无任何计算。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 查表 | constexpr 生成 | 手写表 | 避免出错、可复核 |
| 分支 | if constexpr | 运行时 if | 消除死代码 |
| 校验 | static_assert | 运行时 assert | 假设错误编译期暴露 |
| 复杂度 | 控制 constexpr 深度 | 无限制 | 编译时间与可读性平衡 |

## 7. 性能指标（KPI）
- 运行时开销 = 0。
- 编译期错误在 CI 即暴露。

## 8. 可靠性设计
- 用 static_assert 固化关键常量与位布局假设。
- 编译期结果与运行期结果一致性（纯函数无副作用）。

## 9. 安全设计
- 常量置于 .rodata 只读段，防篡改。
- 消除运行期可被注入的配置解析逻辑。

## 10. 测试与验证策略
- static_assert 作为编译期单测。
- 编译期生成表与参考实现比对。

## 11. 集成与部署
- 编译期计算纳入构建，产物只含只读常量数据。
