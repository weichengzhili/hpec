# 无异常与错误处理

> 模块目录：`workspace/foundation/result/` · 接口文件：`include/result.hpp`

## 0. 问题定位

- **解决什么问题**：错误如何显式传播，不静默丢失。
- **边界标准**：
  1. 错误必须被显式处理或传播，禁止隐式忽略。
- **系统位置**：环 3、环 8。

## 1. 模块定位与目标
在 `-fno-exceptions`（禁用异常）的嵌入式/实时环境下，建立确定性的错误处理机制：错误码、Result/Expected 类型、错误传播与集中处理，保证错误路径可控、可审计、零栈展开不确定性。

**服务场景**：域控、机器人、网关等实时/安全场景（普遍禁用异常）。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 编译 | 禁用异常与 RTTI（-fno-exceptions -fno-rtti） |
| 确定性 | 错误路径无隐式栈展开、无额外开销 |
| 可审计 | 每个错误可追踪、不可静默吞掉 |

## 3. 架构设计

### 3.1 错误处理方案选型
| 方案 | 特点 |
|------|------|
| 错误码 | 简单、零开销，但易遗漏 |
| Result<T,E> | 类型安全，强制检查 |
| Expected<T,E>(C++23) | 标准化的 Result |
| 异常 | 禁用（本模块前提） |
| 错误回调/处理器 | 全局错误集中处理 |

### 3.2 Result 类型设计
- 成功含 T，失败含 E（`result<T,E>`）。
- 必须显式解包，强制处理错误。
- 提供 `and_then`/`map` 链式处理。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `error_code` | 错误码基类型（分层编码） |
| `result<T,E>` | 成功/失败二态类型 |
| `result::is_ok()/value()/error()` | 状态与取值 |
| `result::and_then()/map()` | 链式处理 |
| `ok<T,E>()/err<T,E>()` | 便捷构造 |

## 5. 关键流程与时序
调用返回 Result → 调用者检查解包 → 失败则传播或处理。错误在产生点记录上下文，在边界集中处理（重试/降级/上报）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 异常 | 禁用 | 启用 | 实时确定性、代码体积 |
| 错误类型 | Result<T,E> | 裸错误码 | 类型安全、强制检查 |
| RTTI | 禁用 | 启用 | 减小体积 |
| 错误日志 | 分层编码 | 无 | 可定位、可统计 |

## 7. 性能指标（KPI）
- 错误路径零异常开销。
- 二进制体积相较异常版本明显减小。
- 错误处理覆盖率 100%（无吞错）。

## 8. 可靠性设计
- 编译期强制错误检查（未检查 Result 即告警/错误）。
- 错误码唯一，全局可追踪。

## 9. 安全设计
- 错误信息脱敏，不泄露内部实现细节。
- 安全关键错误触发降级/安全状态。

## 10. 测试与验证策略
- 每条错误路径单测覆盖。
- 故障注入验证降级/恢复。

## 11. 集成与部署
- 错误码集中注册管理，避免冲突。
