# 驱动开发

> 模块目录：`workspace/platform/driver-dev/` · 接口文件：`include/driver.h`

## 0. 问题定位

- **解决什么问题**：platform/字符设备驱动如何正确接入内核设备模型。
- **边界标准**：
  1. 驱动匹配（compatible）与设备树一致（硬约束）。
  2. probe/remove 对称，资源释放无泄漏（硬约束）。
  3. probe 失败不留下半初始化状态（硬约束）。
- **系统位置**：环 3；`hal`、`device-model` → 本模块 → `gic`、`dma-engine`。

## 1. 模块定位与目标
建立 RK3588 自定义外设驱动开发规范：字符设备/平台驱动/外设驱动，遵循 Linux 驱动模型，与设备树、中断、DMA、时钟电源框架集成，保证驱动稳定可维护。

**服务场景**：定制外设驱动、FPGA 协处理器驱动、传感器/执行器驱动。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 模型 | 遵循 Linux 驱动模型（platform/字符设备） |
| 集成 | 使用时钟/中断/DMA/pm_runtime 框架 |
| 约束 | 与设备树 binding 一致（见 devicetree-bsp） |

## 3. 架构设计

### 3.1 驱动分层
```
应用(用户态) → 字符设备/子系统接口 → 驱动 → 硬件(寄存器/中断/DMA)
```

### 3.2 驱动生命周期
| 阶段 | 说明 |
|------|------|
| probe | 匹配设备树，获取资源，初始化 |
| 运行 | 处理 IO/中断 |
| remove | 释放资源 |
| pm_runtime | 空闲下电/唤醒（见 clock-power） |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `platform_driver_ops_t` | 平台驱动操作 |
| `file_operations_t` | 字符设备操作 |
| `driver_register_platform()/register_char()` | 驱动注册 |
| `driver_get_irq/get_clock/get_mmio_base()` | 资源获取 |
| `driver_enable_pm_runtime()` | 电源管理 |

## 5. 关键流程与时序
probe → 获取时钟/中断/内存 → 配置引脚 → 初始化硬件 → 注册设备 → 服务 IO。中断处理走上半部+下半部（见 kernel/irq）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 模型 | platform + 字符设备 | 私有 | 标准、可复用 |
| 资源 | 框架管理 | 手动 | 一致性、可审计 |
| 用户态 | ioctl/mmap | 仅读写 | 按需选择 |
