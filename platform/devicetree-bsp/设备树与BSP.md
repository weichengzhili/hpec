# 设备树与 BSP

> 模块目录：`workspace/platform/devicetree-bsp/` · 接口文件：`dts/rk3588-board.dtsi`

## 0. 问题定位

- **解决什么问题**：硬件配置如何通过 DTS 分层，作为单一数据源。
- **边界标准**：
  1. 硬件描述只有 DTS 一个来源，驱动从 DTS 获取资源（硬约束）。
  2. DTS 与硬件版本对应，无漂移（硬约束）。
  3. DTS 编译通过，dtc 无错误（硬约束）。
- **系统位置**：环 10；`soc-arch` → 本模块；横切环 1、环 3。

## 1. 模块定位与目标
建立 RK3588 设备树（DTS）与 BSP 定制方案：板级硬件描述、驱动绑定、引脚/时钟/中断配置，支撑不同板卡的平台适配。

**服务场景**：定制板卡 BSP、外设使能、多板卡共用内核。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 描述 | 硬件拓扑用 DTS 描述，内核驱动解析 |
| 可复用 | 基础 DTSI + 板级 DTS 覆盖 |
| 约束 | 设备树与驱动 binding 一致 |

## 3. 架构设计

### 3.1 设备树层级
```
rk3588.dtsi（SoC 级）→ rk3588-board.dts（板级）→ dtbo（覆盖层）
```
- SoC 级定义控制器、时钟、中断。
- 板级定义具体外设、引脚、使能。

### 3.2 BSP 组成
| 组件 | 说明 |
|------|------|
| 内核 | Rockchip 定制内核 |
| U-Boot | 板级引导 |
| 设备树 | 硬件描述 |
| 驱动 | 外设驱动 |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| 设备节点 `compatible` | 绑定驱动 |
| `pinctrl-names/pinctrl-0` | 引脚配置 |
| `clocks/interrupts/reg` | 时钟/中断/基址 |
| `dtbo` | 覆盖层（运行时配置） |

## 5. 关键流程与时序
内核启动 → 解析 DTB → 匹配驱动 → 驱动 probe 获取资源 → 初始化外设。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 分层 | dtsi + dts 覆盖 | 单文件 | 复用与定制平衡 |
| 覆盖 | dtbo | 重编译 | 运行时可配 |
| 校验 | DTC 编译检查 | 无 | 提前发现错误 |

## 7. 性能指标（KPI）
- 设备树解析开销可忽略。
- 驱动 probe 成功率（硬件适配正确）。

## 8. 可靠性设计
- 设备树与硬件一致性校验。
- dtbo 应用失败回退。

## 9. 安全设计
- 设备树签名校验（防篡改硬件描述）。

## 10. 测试与验证策略
- DTC 编译、驱动绑定测试。
- 板级外设全量验证。

## 11. 集成与部署
- DTS 版本化，随 BSP 发布。
