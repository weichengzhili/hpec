# RK3588 SoC 架构总览

> 模块目录：`workspace/platform/soc-arch/` · 接口文件：`include/soc.h`

## 0. 问题定位

- **解决什么问题**：RK3588 的基址、外设资源、子系统划分被谁唯一定义，消除各驱动各写一套地址的漂移。
- **边界标准**：
  1. 所有外设基址/中断号只有一个来源，任何驱动不得硬编码地址（硬约束）。
  2. 子系统资源边界可静态验证：无重叠、无遗漏（硬约束）。
  3. 新增外设必须更新本模块的资源表，否则无法通过 CI（硬约束）。
- **系统位置**：环 0；无上游 → 本模块 → `clock-power`、`memory-model`、`gic`。

## 1. 模块定位与目标
建立 RK3588 芯片的整体认识：CPU 集群、总线互连、内存系统、外设布局、NPU/GPU/多媒体子系统，为平台各模块的深入设计提供全局视图与资源预算依据。

**服务场景**：所有基于 RK3588 的域控/网关/IoT/AI/机器人方案选型与架构设计。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 工艺 | 8nm |
| CPU | 4×Cortex-A76 + 4×Cortex-A55（big.LITTLE） |
| 内存 | LPDDR4/4X/5，最高 32GB |
| 算力 | NPU 6 TOPS（INT8） |
| 约束 | 功耗/散热随负载显著变化，需功耗域管理 |

## 3. 架构设计

### 3.1 子系统划分
| 子系统 | 内容 |
|--------|------|
| 计算 | A76/A55 集群、Mali GPU |
| AI | 三核 NPU（6 TOPS） |
| 多媒体 | 8K 视频编解码、ISP、显示 |
| 存储 | eMMC/SD/NVMe(PCIe)/SATA |
| 通信 | 千兆以太网×2、PCIe3.0、USB3.1、CAN |
| 外设 | GPIO、UART、SPI、I2C、PWM、ADC |

### 3.2 总线与内存
- 多层 AXI/NoC 互连，连接 CPU、GPU、NPU、外设。
- 内存控制器支持多通道 LPDDR，提供高带宽给多媒体/AI。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `RK3588_GIC_BASE` 等基址 | MMIO 外设基址 |
| `RK3588_CPU_*_CORES` | CPU 集群配置 |
| `rk3588_irq_t` | 中断线分配（SPI 编号） |
| `soc_peripheral_base()/soc_name()/soc_cpu_count()` | 资源查询 |

## 5. 关键流程与时序
典型 AI 视觉流水线：MIPI-CSI → ISP → 内存 → NPU 推理 → 显示/网络输出，各子系统经总线与内存协同。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 算力 | 大核重负载，小核低功耗 | 同构 | 功耗性能平衡 |
| AI | NPU 而非纯 GPU/CPU | GPU/CPU | 能效比高（TOPS/W） |
| 接口 | PCIe3.0 扩展 | 无 | 接 FPGA/加速卡/存储 |

## 7. 性能指标（KPI）
- CPU 频率、NPU 算力、内存带宽量化。
- 各场景功耗预算（域控/网关满足热设计）。

## 8. 可靠性设计
- 功耗域独立管理，降低相互影响（见 clock-power）。
- 温度监控与降频保护。

## 9. 安全设计
- TrustZone、安全启动、eFuse、加密引擎（见 uboot）。

## 10. 测试与验证策略
- 平台级性能基准（CPU/NPU/内存/总线）。
- 功耗与热测试。

## 11. 集成与部署
- 资源分配表（中断/时钟/引脚）作为平台基线配置。
