# 视频编解码

> 模块目录：`workspace/platform/video-codec/` · 接口文件：`include/codec.h`

## 0. 问题定位

- **解决什么问题**：8K 编解码如何通过 VPU 硬件加速并正确管理码流 buffer。
- **边界标准**：
  1. 硬件编解码与软件缓冲协调，输入输出 buffer 所有权清晰（硬约束）。
  2. 编解码完成事件可靠上报，无竞态（硬约束）。
  3. 码流错误可恢复，不崩溃（硬约束）。
- **系统位置**：环 5；`dma-engine` → 本模块 → `vision-pipeline`。

## 1. 模块定位与目标
建立 RK3588 硬件视频编解码方案：8K H.265/H.264 编解码、多路并发、码流处理，支撑媒体录制、视频传输、监控等场景。

**服务场景**：车载记录、监控、视频会议/传输、媒体网关。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 能力 | 8K 解码、8K 编码（H.265/H.264/VP9/AV1 解码） |
| 并发 | 多路同时编解码 |
| 约束 | 编解码与内存带宽（见 dma-engine） |

## 3. 架构设计
```
采集(V4L2) → 编码器 → 码流 → 网络/存储
码流 → 解码器 → 显示/处理
```

### 3.1 编解码框架
| 组件 | 说明 |
|------|------|
| 硬件编解码器 | VPU，H.265/H.264 等 |
| 驱动框架 | V4L2 mem2mem（m2m） |
| 应用框架 | GStreamer / FFmpeg |

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `codec_format_t` | 编解码格式 |
| `codec_enc_param_t/dec_param_t` | 编解码参数 |
| `codec_session_t` | 会话句柄 |
| `codec_encoder_open/decoder_open()` | 会话创建 |
| `codec_encode()/decode()` | 编解码 |
| `codec_close()` | 关闭 |

## 5. 关键流程与时序
编码：采集帧 → 送入编码器 → 输出码流 → 封装/传输。解码：码流 → 解码器 → 帧 → 显示/处理。缓冲经 dmabuf 零拷贝。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 编解码 | 硬件 VPU | 软件 | 高效低 CPU |
| 框架 | GStreamer/FFmpeg | 私有 | 生态成熟 |
| 缓冲 | dmabuf | 拷贝 | 零拷贝 |

## 7. 性能指标（KPI）
