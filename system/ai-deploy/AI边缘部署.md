# AI 边缘部署

> 模块目录：`workspace/system/ai-deploy/` · 接口文件：`include/ai_deploy.hpp`

## 0. 问题定位

- **解决什么问题**：量化、NPU、MLOps 如何集成部署。
- **边界标准**：
  1. 量化精度达标，NPU 部署正确，MLOps 闭环。
- **系统位置**：环 7、环 10。

## 1. 方案定位与目标
面向 AI 模型在边缘设备（RK3588）的规模化部署方案：覆盖模型转换/量化、NPU 推理运行时、视觉流水线、MLOps 模型管理与性能评测，形成可运营的 AI 边缘推理平台。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 算力 | RK3588 NPU 6 TOPS |
| 精度 | 量化精度达标（见 ai/quantization） |
| 部署 | 多模型、多路、可动态更新 |
| 约束 | 低延迟、低功耗、内存受限 |

## 3. 架构设计

### 3.1 部署链路
```
训练模型 → 转换/量化(RKNN) → 评测 → 模型仓库 → 下发(OTA) → 推理运行时 → 监控
```

### 3.2 运行时架构
```
采集(V4L2) → 预处理 → 推理(NPU) → 后处理 → 结果/业务
```
- 多模型管理、多路并发。
- 零拷贝 DMA 数据通路（见 platform/dma-engine）。

### 3.3 MLOps 闭环
- 模型版本化、评测门禁。
- 云边协同下发、A/B 切换、回滚（见 ai/mlops）。
- 性能/精度监控与优化（见 ai/performance）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `convert` | 模型转换/量化 |
| `runtime` | NPU 推理 |
| `vision` | 视觉流水线 |
| `mlops` | 模型管理 |

## 5. 关键流程与时序
模型注册 → 下发 → 校验 → 原子切换 → 推理服务 → 监控 → 异常回滚。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 精度 | INT8 量化 | FP32 | NPU 能效 |
| 部署 | A/B 切换 | 覆盖 | 可靠性 |
| 监控 | 指标闭环 | 无 | 质量 |

## 7. 性能指标（KPI）
- 端到端延迟、多路吞吐。
- 量化精度损失、功耗。
- 下发/回滚成功率。

## 8. 可靠性设计
- 推理超时看护、异常恢复。
- 模型切换原子性、失败回滚。

## 9. 安全设计
- 模型加密/签名、数据隐私（见 ai/security）。

## 10. 测试与验证策略
- 精度/性能回归、多路压力测试。
- 下发/回滚故障注入。

## 11. 集成与部署
- 与云端 MLOps 平台联动，规模化运营。
