# 汽车域控

> 模块目录：`workspace/system/automotive/` · 接口文件：`include/automotive_system.hpp`

## 0. 问题定位

- **解决什么问题**：汽车域控的功能安全/信息安全/实时如何满足 ASIL 等级。
- **边界标准**：
  1. 功能安全目标（ASIL）明确，安全机制覆盖（硬约束）。
  2. fail-safe/fail-operational 状态定义清楚（硬约束）。
  3. 安全相关路径有诊断覆盖率（度量项）。
- **系统位置**：环 8；横切全链，主挂环 8。

## 1. 方案定位与目标
面向汽车域控制器（座舱域/智能驾驶域/车身域）的整机软件与硬件架构，以 RK3588 为算力核心，融合舱内感知 AI、实时控制、车载网络与功能安全/信息安全，满足 ISO 26262 / ISO 21434 要求。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 功能安全 | ISO 26262，按功能 ASIL 定级 |
| 信息安全 | ISO 21434，安全启动、通信加密 |
| 实时 | 控制类任务有界延迟（PREEMPT_RT） |
| 网络 | 车载以太网（TSN）、CAN/CAN-FD |
| 升级 | A/B 分区 OTA，失败回退 |
| 约束 | 温度/振动/EMC 车规环境 |

## 3. 架构设计

### 3.1 软硬件分层
```
应用层（座舱/ADAS/车身控制）
  ├─ 中间件（AUTOSAR AP/CP 或 SOA 中间件）
  ├─ 操作系统（Linux + PREEMPT_RT / 多系统隔离）
  ├─ 驱动/BSP（RK3588 平台）
硬件层（RK3588 + 外设 + 安全 MCU/PMIC）
```

### 3.2 关键子系统
| 子系统 | 说明 |
|--------|------|
| 计算域 | RK3588（A76 跑应用，A55 跑控制） |
| 感知 | MIPI-CSI 相机 + NPU（舱内检测/环视） |
| 网络 | 车载以太网（TSN）+ CAN/CAN-FD |
| 显示 | 仪表/中控（GPU + 多路显示） |
| 安全岛 | 独立安全 MCU 做安全监控 |

### 3.3 功能安全设计
- 安全关键功能隔离在专用核/专用分区。
- 安全监控 MCU 独立看门狗、关断路径。
- ASIL 分解与冗余设计。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `perception` | 感知（NPU 舱内/环视） |
| `control` | 实时控制（PREEMPT_RT） |
| `vehicle_net` | 车载网络（TSN/CAN-FD） |
| `display` | 显示（GPU 多路） |
| `ota` | A/B 升级 |
| `safety` | 功能安全监控 |

## 5. 关键流程与时序
启动（安全启动链）→ 分区加载 → 功能安全自检 → 感知/控制运行 → OTA 升级（A/B）。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 隔离 | 核心/分区隔离 | 共享 | 功能安全 |
| 系统 | Linux + 安全 MCU | 纯 Linux | 性能与安全平衡 |
| 升级 | A/B OTA | 单分区 | 可靠性 |
| 感知 | NPU 本地推理 | 云端 | 低延迟/隐私 |

## 7. 性能指标（KPI）
- 控制任务最坏延迟（< 阈值）。
- 感知端到端延迟（< 阈值）。
- 启动时间、OTA 成功率、功能安全覆盖率。

## 8. 可靠性设计
- 安全 MCU 独立看门狗、电源关断。
- 冗余通信、故障降级。
- A/B 回退（见 platform/uboot）。

## 9. 安全设计
- 安全启动 + 逐级校验。
- 车载网络加密（SecOC）、入侵检测。
- 最小权限、访问控制（见 kernel/security）。

## 10. 测试与验证策略
- 功能安全验证（V 模型，ASIL 覆盖）。
- 环境测试（温度/振动/EMC）。
- 信息安全渗透测试。

## 11. 集成与部署
- 车规 BOM、软件版本与功能安全证书管理。

## 12. 参考资料
- ISO 26262、ISO 21434、AUTOSAR 规范。
- 车载以太网（TSN）标准。
