# 模块问题定义

> 每个模块回答三件事：**解决什么问题、边界标准是什么、在系统问题链的什么位置。**
> 边界标准是可验证的约束，不是口号。每条标准都对应一种检测手段：编译期断言、运行时校验、测试、CI 检查、静态分析或测量。

配套文档：[系统问题链](系统问题链.md)

## 使用约定

- **硬约束**：必须满足，否则拒绝合并。
- **度量项**：需量化达标，写入测试报告。
- **位置**：沿用《系统问题链》的环编号（0~10），"上游 → 本模块 → 下游"表示因果衔接。

## 环 0：物理真相

### `../../platform/soc-arch` —— 地址与子系统的唯一真相源

- **解决**：RK3588 的基址、外设资源、子系统划分被谁唯一定义，消除各驱动各写一套地址的漂移。
- **边界标准**：
  1. 所有外设基址/中断号只有一个来源，任何驱动不得硬编码地址（硬约束）。
  2. 子系统资源边界可静态验证：无重叠、无遗漏（硬约束）。
  3. 新增外设必须更新本模块的资源表，否则无法通过 CI（硬约束）。
- **位置**：环 0；无上游 → 本模块 → `clock-power`、`memory-model`、`gic`。

### `../../platform/clock-power` —— 访问外设的前置三条件

- **解决**：外设访问前，如何保证"时钟开 + 复位释放 + 电源域上电"，并在低功耗/DVFS 下可预测恢复。
- **边界标准**：
  1. 任何外设驱动写寄存器前必须满足三条件，违反即断言或返回错误码（硬约束）。
  2. 每个电源域的掉电→唤醒路径有明确的恢复清单和延迟上界（度量项）。
  3. DVFS 切换期间对依赖外设的访问必须冻结或重试，禁止读到中间态（硬约束）。
- **位置**：环 0；`soc-arch` → 本模块 → `../../boot/startup`、`scheduler`、`npu`。

### `../../fpga/timing` —— 时序收敛是功能正确性的一部分

- **解决**：FPGA 逻辑在温度/电压/工艺偏差下 setup/hold 是否仍满足，避免时序相关的随机错误。
- **边界标准**：
  1. 所有时钟路径 STA 收敛，WNS/TNS = 0（硬约束）。
  2. 约束文件覆盖 100% 时钟，无未约束时钟域（硬约束）。
  3. 无负 slack 进入硬件，违例必须修完再交付（硬约束）。
- **位置**：环 0；无上游 → 本模块 → `../../fpga/cdc`、`../../fpga/axi`、`../../fpga/serdes`。

### `../../fpga/cdc` —— 跨时钟域的信号一致性

- **解决**：跨时钟域信号如何避免亚稳态和多位数据不一致。
- **边界标准**：
  1. 单比特 CDC 必须双触发器同步器，禁止裸信号跨域（硬约束）。
  2. 多比特 CDC 必须格雷码/握手/异步 FIFO，禁止多位直接同步（硬约束）。
  3. CDC 路径通过形式验证或 CDC 工具检查，无未处理违例（硬约束）。
- **位置**：环 0；`../../fpga/timing` → 本模块 → `../../fpga/fifo`、`../../fpga/axi`。

## 环 1：启动

### `../../boot/startup` —— 从复位向量到可运行态

- **解决**：从复位向量到 `main`，如何保证内存段正确初始化、栈可用、镜像可信。
- **边界标准**：
  1. `.data` 拷贝和 `.bss` 清零必须早于任何 C 运行，顺序可静态验证（硬约束）。
  2. 启动自检（`.data` 校验和、栈水位）在 `main` 前完成（硬约束）。
  3. 冷/热/看门狗/软复位四种路径到达一致的可运行态（度量项）。
- **位置**：环 1；`clock-power` → 本模块 → `memory-model`、`gic`。

### `../../platform/uboot` —— 多级启动的信任链

- **解决**：多级启动中 DDR 训练、安全启动校验、A/B 槽选择的信任链如何闭环。
- **边界标准**：
  1. DDR 训练完成标志是任何 DDR 访问的前置条件，失败即停止（硬约束）。
  2. 镜像签名校验失败必须回退槽或安全态，禁止执行未验签镜像（硬约束）。
  3. A/B 槽回退有明确条件和重试上限（硬约束）。
- **位置**：环 1；`clock-power` → 本模块 → `../../boot/startup`。

## 环 2：可见性

### `../../memory/memory-model` —— 内存布局与寻址的唯一定义

- **解决**：存储类、内存段、对齐、端序、ABI 如何被唯一定义，成为所有内存访问正确性的地基。
- **边界标准**：
  1. 所有内存段起始/大小/属性唯一，无重叠无遗漏（硬约束）。
  2. 对齐与端序假设用静态断言固化，违反即编译错误（硬约束）。
  3. MMIO 区域与普通内存属性严格分离（硬约束）。
- **位置**：环 2；`../../boot/startup` → 本模块 → `memory-barrier`、`../../kernel/mm`、`../../kernel/dma`。

### `../../memory/memory-barrier` —— 访问序与可见性

- **解决**：MMIO 访问和 DMA 共享内存如何保证正确的可见性和顺序。
- **边界标准**：
  1. MMIO 访问必须 `volatile` + 必要屏障，禁止被编译器优化掉（硬约束）。
  2. DMA 共享内存的 clean/invalidate 时机明确，CPU 与设备视图一致（硬约束）。
  3. 内存序分类（MMIO/DMA/共享变量）有规则，禁止靠猜（硬约束）。
- **位置**：环 2；`memory-model` → 本模块 → `../../driver/bit-register`、`dma-engine`、`../../kernel/lock`。

### `../../kernel/mm` —— 页表与内存回收

- **解决**：内核页表、slab、映射、回收如何正确建立和管理地址空间。
- **边界标准**：
  1. 页表映射权限与 memory map 一致，无越权映射（硬约束）。
  2. 内存回收不破坏在用页（引用计数正确）（硬约束）。
  3. 缺页/越权行为可预测，产生可捕获异常（硬约束）。
- **位置**：环 2；`memory-model` → 本模块 → `scheduler`、`../../kernel/dma`。

### `../../kernel/dma` —— 内核态 DMA 的地址与一致性

- **解决**：内核态 DMA buffer 的映射、cache 一致性、IOMMU 配置如何保证设备访问正确内存。
- **边界标准**：
  1. DMA buffer 用 DMA API 分配/映射，禁止裸物理地址（硬约束）。
  2. streaming DMA 的 direction 与 cache 操作一致（硬约束）。
  3. IOMMU 使设备只能访问授权内存，越权即 fault（硬约束）。
- **位置**：环 2；`memory-model`、`memory-barrier` → 本模块 → `../../platform/dma-engine`。

## 环 3：控制

### `../../driver/bit-register` —— 寄存器字段读写无竞态

- **解决**：寄存器字段读写如何避免读改写竞态、误清标志、位宽错误。
- **边界标准**：
  1. 字段访问用强类型/掩码，禁止裸移位魔术数（硬约束）。
  2. W1C/WO/RO 字段语义被强制（编译期或运行时断言）（硬约束）。
  3. RMW 对 W1C 字段安全，不误清其他位（硬约束）。
- **位置**：环 3；`memory-barrier` → 本模块 → `../../driver/hal`、`../../driver/pac-hal`。

### `../../driver/hal` —— 硬件依赖的抽象边界

- **解决**：硬件依赖如何通过接口抽象，使上层可测试、可替换。
- **边界标准**：
  1. HAL 接口不泄漏硬件裸指针，依赖注入可 mock（硬约束）。
  2. 每个 HAL 实现可脱离真实硬件跑单元测试（硬约束）。
  3. 错误返回统一 Result/错误码，无隐式失败（硬约束）。
- **位置**：环 3；`bit-register` → 本模块 → `driver-dev`、`platform-driver`。

### `../../driver/pac-hal` —— 寄存器访问层从数据源生成

- **解决**：外设寄存器如何从单一数据源生成类型安全访问，杜绝手写地址错误。
- **边界标准**：
  1. 寄存器访问层由 SVD/IP-XACT 生成，禁止手写（硬约束）。
  2. 生成的 API 类型安全（字段级、位宽检查）（硬约束）。
  3. 生成物与源数据源漂移通过 CI diff 检测（硬约束）。
- **位置**：环 3；`bit-register` → 本模块 → `driver-dev`；横切环 10。

### `../../platform/driver-dev` —— 驱动接入内核设备模型

- **解决**：platform/字符设备驱动如何正确接入内核设备模型。
- **边界标准**：
  1. 驱动匹配（compatible）与设备树一致（硬约束）。
  2. probe/remove 对称，资源释放无泄漏（硬约束）。
  3. probe 失败不留下半初始化状态（硬约束）。
- **位置**：环 3；`hal`、`device-model` → 本模块 → `gic`、`dma-engine`。

## 环 4：事件

### `../../platform/gic` —— 中断路由与配置

- **解决**：GIC-600 的中断路由、优先级、触发方式如何被正确配置。
- **边界标准**：
  1. 每个 IRQ 的触发方式（电平/边沿）、优先级、affinity 明确且正确（硬约束）。
  2. 中断清除顺序正确：先清 source 再 EOI（硬约束）。
  3. 共享中断线能正确识别触发源（硬约束）。
- **位置**：环 4；`driver-dev` → 本模块 → `../../kernel/irq`、`interrupt-critical`。

### `../../kernel/irq` —— 上下半部边界

- **解决**：上半部/下半部如何划分，保证 ISR 短、重活不阻塞中断。
- **边界标准**：
  1. ISR 内禁止阻塞调用和长操作，耗时上界明确（硬约束）。
  2. 下半部（softirq/tasklet/workqueue）职责清晰（硬约束）。
  3. 中断风暴有检测和降级（硬约束）。
- **位置**：环 4；`gic` → 本模块 → `interrupt-critical`、`workqueue`。

### `../../concurrency/interrupt-critical` —— 中断与主循环的安全交互

- **解决**：中断与主循环共享数据如何无锁/原子地安全交互。
- **边界标准**：
  1. 关中断临界区时间有上界（如 < N μs，N 按实时预算定）（度量项）。
  2. SPSC 队列生产/消费边界明确，无数据竞争（硬约束）。
  3. 中断上下文禁止任何可能阻塞的调用（硬约束）。
- **位置**：环 4；`../../kernel/irq` → 本模块 → `fsm`、`lock`；横切环 6。

### `../../platform/gpio-pinctrl` —— 引脚复用与 GPIO 中断

- **解决**：引脚复用和 GPIO 控制如何正确配置，GPIO 中断如何可靠触发。
- **边界标准**：
  1. 引脚复用配置与原理图一致，无冲突复用（硬约束）。
  2. GPIO 中断触发沿/电平配置正确（硬约束）。
  3. GPIO 读取反映真实电平，去抖策略明确（硬约束）。
- **位置**：环 4；`driver-dev` → 本模块 → `gic`。

### `../../concurrency/rtic` —— 硬实时中断驱动的并发

- **解决**：硬实时中断驱动并发如何用 RTIC 框架保证无数据竞争和确定性调度。
- **边界标准**：
  1. 资源共享编译期检查，无运行时数据竞争（硬约束）。
  2. 任务优先级静态确定，满足实时调度（硬约束）。
  3. 中断处理确定性，无动态分配（硬约束）。
- **位置**：环 4；`interrupt-critical` → 本模块；横切环 6。

## 环 5：数据

### `../../platform/dma-engine` —— 数据搬运与缓存一致性

- **解决**：DMA 通道如何正确搬运数据并处理缓存一致性和错误。
- **边界标准**：
  1. 传输完成前 CPU 不访问该 buffer，所有权明确（硬约束）。
  2. cache clean（D→M）与 invalidate（M→D）时机正确（硬约束）。
  3. DMA 错误（超时/部分传输）有检测和恢复，不死等（硬约束）。
- **位置**：环 5；`memory-barrier`、`gic` → 本模块 → `mipi-csi`、`video-codec`。

### `../../memory/resource-scheduling` —— 内存资源的准入与回收

- **解决**：有限内存资源在多消费者竞争下如何准入、配额、回收，保证关键任务不饿死。
- **边界标准**：
  1. 准入判断有界（无动态分配），最坏复杂度明确（硬约束）。
  2. 关键消费者预留额度不被低优先级挤占（硬约束）。
  3. 回收有边界，不回收关键资源（硬约束）。
- **位置**：环 5；`memory-pool` → 本模块 → `dma-engine`、`scheduler`；横切环 7。

### `../../memory/memory-pool` —— 确定性固定块分配

- **解决**：无 GC 受限环境下提供确定性 O(1) 固定块分配，避免碎片和不可预测的 malloc。
- **边界标准**：
  1. 分配/释放 O(1)，无遍历（硬约束）。
  2. 长期运行无碎片累积（浸泡测试验证）（度量项）。
  3. 越界/双重释放可检测（魔数校验）（硬约束）。
- **位置**：环 5；`memory-model` → 本模块 → `resource-scheduling`、`dma-engine`。

### `../../memory/allocator` —— C++ 容器接入确定性池

- **解决**：C++ 容器如何接入确定性内存池，满足 Allocator 概念。
- **边界标准**：
  1. 满足 std::allocator 概念，STL 容器可直接使用（硬约束）。
  2. 与 C 版 `memory_pool` 语义一致，`owns()` 校验归属（硬约束）。
  3. 移动语义正确，禁止拷贝（资源唯一）（硬约束）。
- **位置**：环 5；`memory-pool` → 本模块 → `resource-scheduling`。

### `../../memory/ownership` —— 编译期保证单一所有者

- **解决**：buffer 所有权如何在编译期保证单一所有者，杜绝悬垂、双重释放、use-after-free。
- **边界标准**：
  1. 单一所有权，借用检查编译期强制（硬约束）。
  2. 共享借用用原子/RefCell，无数据竞争（硬约束）。
  3. unsafe 最小化，不绕过所有权语义（硬约束）。
- **位置**：环 5；`memory-pool`、`memory-barrier` → 本模块；横切环 6。

### `../../platform/mipi-csi` —— 相机采集零拷贝流水线

- **解决**：相机采集从 sensor 到 ISP 到 DDR 如何零拷贝且不丢帧。
- **边界标准**：
  1. 采集→ISP→DDR 全程零拷贝，buffer 所有权转移不 memcpy（硬约束）。
  2. buffer 循环使用，DMA 完成后才归还池（硬约束）。
  3. 丢帧/错误有计数和上报，不死等（硬约束）。
- **位置**：环 5；`dma-engine` → 本模块 → `vision-pipeline`。

### `../../platform/video-codec` —— 8K 编解码的码流管理

- **解决**：8K 编解码如何通过 VPU 硬件加速并正确管理码流 buffer。
- **边界标准**：
  1. 硬件编解码与软件缓冲协调，输入输出 buffer 所有权清晰（硬约束）。
  2. 编解码完成事件可靠上报，无竞态（硬约束）。
  3. 码流错误可恢复，不崩溃（硬约束）。
- **位置**：环 5；`dma-engine` → 本模块 → `vision-pipeline`。

### `../../platform/pcie-usb-storage` —— IO 数据流与热插拔

- **解决**：PCIe/USB/存储的 IO 数据流如何正确传输，热插拔如何安全。
- **边界标准**：
  1. IO 数据 buffer 的 cache 一致性正确（硬约束）。
  2. 传输错误/超时处理完整（硬约束）。
  3. 热插拔/拔插生命周期安全，无 use-after-free（硬约束）。
- **位置**：环 5；`dma-engine` → 本模块。

### `../../ai/vision-pipeline` —— 视觉流水线的延迟与所有权

- **解决**：采集→预处理→推理→后处理流水线如何零拷贝串联、延迟可控。
- **边界标准**：
  1. 各阶段 buffer 所有权明确，无隐式拷贝（硬约束）。
  2. 端到端延迟有预算，各阶段耗时可测量（度量项）。
  3. 阶段失败可降级（如跳过后处理）（硬约束）。
- **位置**：环 5；`mipi-csi` → 本模块 → `npu-runtime`、`performance`。

### `../../fpga/fifo` —— 片上 FIFO 的跨时钟域可靠性

- **解决**：片上 FIFO 如何保证跨时钟域数据不丢、不乱序。
- **边界标准**：
  1. 满/空标志正确，无数据丢失或重复（硬约束）。
  2. 跨时钟域 FIFO 用格雷码指针，无亚稳态（硬约束）。
  3. 深度满足突发流量，有背压防溢出（硬约束）。
- **位置**：环 5；`../../fpga/cdc` → 本模块 → `../../fpga/axi`。

### `../../fpga/axi` —— 总线握手与突发正确性

- **解决**：AXI 总线上的握手、突发、乱序如何正确实现。
- **边界标准**：
  1. 握手协议（VALID/READY）正确，无死锁（硬约束）。
  2. 突发长度/对齐满足 AXI 规范（硬约束）。
  3. outstanding 事务和乱序响应正确处理（硬约束）。
- **位置**：环 5；`../../fpga/fifo`、`../../fpga/timing` → 本模块 → `../../fpga/serdes`。

### `../../fpga/serdes` —— 高速链路的建立与可靠性

- **解决**：SerDes 高速接口的链路建立、对齐、误码如何可靠。
- **边界标准**：
  1. 链路训练/对齐完成标志明确（硬约束）。
  2. 误码/失锁有检测和重训练（硬约束）。
  3. 时序约束满足（时序收敛）（硬约束）。
- **位置**：环 5；`../../fpga/axi`、`../../fpga/timing` → 本模块。

## 环 6：并发
