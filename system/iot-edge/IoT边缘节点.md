# IoT 边缘节点

> 模块目录：`workspace/system/iot-edge/` · 接口文件：`include/iot_edge.hpp`

## 1. 方案定位与目标
面向高端 IoT 边缘节点的整机方案，以 RK3588 为算力核心，融合边缘推理、传感器融合、无线连接（WiFi6/5G/LoRa）与设备管理，实现本地智能与云端协同。

## 2. 需求与约束
| 类别 | 要求 |
|------|------|
| 算力 | NPU 边缘推理（多路视觉） |
| 连接 | WiFi6 / 5G / 以太网 / LoRa |
| 功耗 | 待机/负载功耗分档管理 |
| 管理 | 设备管理、远程升级（OTA） |
| 约束 | 长时间无人值守、户外环境 |

## 3. 架构设计

### 3.1 软硬件分层
```
应用层（边缘推理/数据服务/设备管理 Agent）
  ├─ AI 推理（NPU，见 ai/npu-runtime）
  ├─ 系统层（Linux + 功耗管理）
  ├─ 驱动/BSP（RK3588 + 传感器/无线）
硬件层（RK3588 + 传感器 + 无线模组）
```

### 3.2 关键能力
| 能力 | 说明 |
|------|------|
| 边缘推理 | NPU 本地推理（检测/识别） |
| 传感器融合 | 相机/温湿度/环境多源融合 |
| 无线 | WiFi6/5G 回传，LoRa 组网 |
| 功耗 | 功耗域分档 + 待机休眠 |

### 3.3 设备管理
- 设备注册/认证/状态上报。
- 远程配置、OTA 升级（A/B）。
- 本地自治（断网时本地推理与缓存）。

## 4. 接口设计

| 接口 | 说明 |
|------|------|
| `infer` | 边缘推理 |
| `sensor` | 传感器融合 |
| `radio_if` | 无线连接 |
| `power` | 功耗管理 |
| `device_mgmt` | 设备管理 |

## 5. 关键流程与时序
采集 → 本地推理 → 结果/数据上云 → 云端分析/下发。断网时本地自治 + 缓存续传。

## 6. 设计决策与权衡
| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 推理 | 本地 NPU | 云端 | 低延迟/隐私/省带宽 |
| 连接 | 多模无线 | 单一 | 覆盖/可靠性 |
| 功耗 | 分档管理 | 全速 | 续航/散热 |

## 7. 性能指标（KPI）
- 边缘推理延迟/功耗。
- 待机功耗、续航。
- OTA 成功率、设备在线率。

## 8. 可靠性设计
- 看门狗、断网续传、本地自治。
- 远程诊断与恢复。

## 9. 安全设计
- 设备认证、TLS、安全启动。
- 数据加密与最小化上传（隐私）。

## 10. 测试与验证策略
- 功耗测试、断网/重连测试。
- 长时间无人值守稳定性。

## 11. 集成与部署
- 户外防护、无线认证、设备批量管理。

## 12. 参考资料
- IoT 设备管理协议（LwM2M/MQTT）。
- 低功耗设计最佳实践。
